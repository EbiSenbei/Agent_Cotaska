# Cotaska UIモーション基準

## 1. 目的

Cotaskaの操作感を「静かで、速く、信頼できる」に揃える。モーションは装飾ではなく、操作へのフィードバック、状態の理解、空間的一貫性、突然の変化の緩和に限って使用する。

Apple由来の物理的な操作原則は、ドラッグとリサイズなどポインターが対象を直接操作する場面だけへ適用する。外観やbounceをApple風にすることは目的としない。

## 2. 適用範囲

- 共通: サイドバー、ボタン、ダイアログ、ポップオーバー、通知、進捗表示
- タスク管理: タスク行、Drag to reorder、子タスク化、詳細ペイン、サブタスクペイン
- AI連携: AIスレッド、処理中表示、ストリーミング表示、コンテキストペイン
- 設定・起動・更新: 起動進捗、更新確認、ダウンロード進捗、更新通知

タスク選択、検索入力、ナビゲーション、キーボード操作などの高頻度操作には、画面移動や待ち時間を生むモーションを追加しない。

## 3. 動かすかどうかの判断

| 利用頻度 | 方針 | 例 |
| --- | --- | --- |
| 1日100回以上、キーボード起点 | 動かさない | タスク選択、検索、ショートカット、主要ナビゲーション |
| 1日数十回 | 削除または100〜120msの色・透明度変化だけ | hover effect、頻繁な展開操作 |
| ときどき | 125〜250msの標準モーションを許可 | 小型popover、toast、dropdown |
| 稀・初回 | 目的が明確な場合だけ演出を許可 | 初回案内、重要な完了フィードバック |

採用できる目的は、Feedback、Spatial consistency、State indication、Preventing a jarring change、Explanationのいずれかとする。単に「見た目が面白い」は採用理由にしない。

## 4. 共通値

```css
:root {
  --motion-instant: 100ms;
  --motion-fast: 120ms;
  --motion-standard: 160ms;
  --motion-progress: 200ms;
  --ease-out: cubic-bezier(0.23, 1, 0.32, 1);
  --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
  --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
}
```

| 対象 | 値・判断 |
| --- | --- |
| hoverの色・透明度 | 100〜120ms、`ease` |
| press feedback | 100〜160ms。高頻度操作へ一律追加しない |
| 小型popover | 125〜200ms、`--ease-out`、triggerをTransform originとする |
| dropdown | 150〜250ms、`--ease-out` |
| modal | 200〜300msを原則とする。Cotaskaの小型確認modalはEnter 160ms、Exit 120msとし、画面中央をTransform originとする |
| 画面上の移動・変形 | `--ease-in-out` |
| spinnerなど一定速度のLoop | `linear` |

UIモーションは原則300ms未満とする。`ease-in`、`transition: all`、`scale(0)`は使用しない。

## 5. パフォーマンス

- 補間するプロパティは`transform`と`opacity`を原則とする。
- `width`、`height`、`top`、`left`、`margin`、`padding`を連続補間しない。
- 決定進捗は幅100%の要素へ`transform-origin: left center`と`scaleX(0〜1)`を適用する。
- 反復するPulseで`box-shadow`を補間しない。必要な処理中表示はopacity-onlyを優先する。
- JavaScriptのフレームループは使用せず、既知の動きはCSS transitionまたはanimationを用いる。

## 6. アクセシビリティ

```css
@media (prefers-reduced-motion: reduce) {
  .moving-status {
    animation: none;
  }
}

@media (hover: hover) and (pointer: fine) {
  .control:hover {
    /* hover可能端末だけの視覚変化 */
  }
}
```

Reduced motionでは状態表示そのものを消さない。spinnerは静的リング、処理中は静的ドット、起動中は静的バー、決定進捗は短いopacityまたはscaleの更新として理解可能な状態を維持する。

hover固有の反応はhover可能かつfine pointerの端末へ限定する。`:focus-visible`、`.active`、disabled、error、処理中などの意味状態はmedia queryの外に置く。

## 7. コンポーネント別基準

### 7.1 サイドバーと高頻度操作

- 選択結果は即時に反映する。
- hoverはopacity・background-colorだけを100〜120msで補間する。
- 画面切替、タスク選択、検索結果へEnter / ExitやPage transitionを追加しない。

### 7.2 ポップオーバー、通知、ダイアログ

- triggerに結び付くpopoverはOrigin-aware animationを使用する。modalは中央起点のままとする。
- Enter / Exitを実装する場合は`opacity`と`scale(.95〜.97)`を用い、`scale(0)`を使わない。
- 永続的な更新通知は静的な色と状態ドットで示し、注意を引き続けるLoopやPulseを使わない。

### 7.3 起動・更新・AI処理中

- 不確定進捗のLoopは一定速度とし、reduced motionでは静止させる。
- 決定進捗は`scaleX()`で表示し、百分率や説明文を正本の状態表示とする。
- AI処理中のPulseはopacity-onlyとし、状態終了時に即時停止する。

### 7.4 Drag to reorderとリサイズ

- ポインター移動へ1対1で追従し、遅延、easing、spring、momentumを加えない。
- pointer-down直後からdrag元、操作中ハンドル、挿入位置、子化、禁止状態を表示する。
- `mouseup`、window `blur`、component unmountのいずれでも操作中状態を解除する。
- タスク並び替えはCHG-088のHTML5 Drag & Drop方式を維持する。Pointer Eventsや別ライブラリへの置換は別の仕様判断とする。

### 7.5 Copy toastと確認modalの入退場

Copy toastと、ごみ箱確認・AIスレッド名変更のmodalは、突然の表示切替を避け、表示元との空間関係と状態変化を伝えるためにだけEnter / Exitを使用する。

#### 共通presence lifecycle

| 状態 | DOM | 表示状態 | 遷移条件 |
| --- | --- | --- | --- |
| Unmounted | なし | 非表示 | 表示要求でMounted / Enterへ移る |
| Enter | あり | `@starting-style`の初期値から表示値へ遷移 | ブラウザーのCSS transitionで自動的にSettledへ到達する |
| Settled | あり | 通常表示 | close要求でExitへ移る |
| Exit | あり | `data-motion-state="exiting"`の終了値へ遷移 | overlayまたはtoast自身の`opacity` transitionendでUnmountする |

- Exit完了検知は、子要素からbubbleしたイベントを除外し、対象要素自身の`opacity`だけを採用する。
- transitionendが発火しない場合に備え、200msのfallback timeoutでUnmountする。コンポーネントunmount時はtimeoutを必ず解除する。
- Exit中に再表示された場合はfallbackを解除し、同じDOMをSettledへ戻す。CSS transitionが現在の画面上の値からretargetするため、keyframesや新規ライブラリは使わない。
- Exit中はpointer eventを無効化し、実行ボタンもdisabledにして二重処理を防ぐ。表示要求による再openは拒否せずretargetできる。

#### Copy toast

- 右下の画面下辺を出入り口とし、Enterは`opacity: 0; transform: translateY(100%)`から`opacity: 1; transform: translateY(0)`へ160ms、`--ease-out`で遷移する。
- 表示時間は従来どおり2400msとする。Exitは同じ下辺へ120ms、`--ease-out`で戻す。
- 連続コピー時は表示時間を2400msへ更新する。Exit中なら同じDOMを現在値からSettledへ戻し、表示中なら成功・失敗の文言と色を即時更新する。
- `role="status"`と`aria-live="polite"`を維持し、成功・失敗の意味は既存の文言と色で示す。

#### 確認modal

- overlayは`opacity: 0`から`1`、dialogは`opacity: 0; transform: scale(.97)`から`opacity: 1; transform: scale(1)`へ160ms、`--ease-out`でEnterする。
- Exitはoverlayとdialogを同じ初期値へ120ms、`--ease-out`で戻す。dialogのTransform originは画面中央とする。
- キャンセル、背景クリック、Escape、確定操作のすべてで同じExit lifecycleを通る。確定処理自体は従来どおり即時開始し、表示だけをExit完了まで保持する。
- `role="dialog"`、`aria-modal="true"`、label、既存のfocus動作を維持する。

#### Reduced motion

`prefers-reduced-motion: reduce`ではtoastのtranslateとdialogのscaleを無効化し、Enter / Exitとも120msのopacity-only transitionに置き換える。状態表示とtransitionendによるlifecycleは維持する。

## 8. 用語

設計書とタスクでは次の用語を使用する。

| 用語 | Cotaskaでの意味 |
| --- | --- |
| Enter / Exit | 要素が追加・削除されるときの入退場 |
| Transform origin | scaleまたはrotateの起点 |
| Origin-aware animation | triggerから現れるように起点を合わせた動き |
| Press / Tap feedback | 押下を伝える短い視覚反応 |
| Drag to reorder | タスクを掴んで順序または親子関係を変更する操作 |
| Pulse | scaleまたはopacityを反復して状態を示す動き |
| Loop | 一定回数または無限に繰り返す動き |
| Interruptible animation | 実行途中でも現在位置から向きを変えられる動き |
| Reduced motion | 利用者設定に従い移動や反復を弱めること |
| Layout thrashing | width等の補間でlayout計算を繰り返し、jankを招く状態 |

## 9. 禁止事項

- キーボード起点または高頻度画面切替のアニメーション
- `transition: all`
- UIへの`ease-in`
- `scale(0)`からの表示
- trigger付きpopoverの中央起点表示
- `width`や`height`の連続アニメーション
- 反復する`box-shadow`、過度なglow、理由のないbounce
- reduced motion時に状態表示まで消す実装
- CHG-088のDrag & Drop方式を設計判断なしに置換すること

- Node.js 22.14.0で`npm test`と`npm run build`を実行する。
- DevToolsのAnimationsを10%再生し、起点、補間対象、終了位置を確認する。
- `prefers-reduced-motion: reduce`で移動・反復が抑制され、状態を理解できることを確認する。
- Windows版Electronでリサイズを途中中止し、cursorやactive表示が残らないことを確認する。
- タスク選択、検索、ナビゲーションへ体感上の待ち時間が増えていないことを確認する。
