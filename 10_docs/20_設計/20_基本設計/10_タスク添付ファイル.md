# タスク添付ファイル（CHG-140）

## PDF・PowerPointプレビュー（CHG-142）

共通DetailPaneの添付一覧にPDF/ppt/pptxの「プレビュー」を追加し、本文プレビューのattachments/ファイル名リンクからも同じモーダルを開く。既存のファイル名ボタンは外部アプリ起動を維持する。メイン詳細・独立詳細の両方に適用する。モーダルは前後ページ（PowerPointではスライド）、幅基準25〜300%の拡大縮小、幅に合わせる、閉じる、Escape、外部アプリで開くを提供する。フォーカスはdialogに閉じ込め、終了時に起点へ戻す。タスク切替・添付変更時は閉じる。

PDFはPDF.js（pdfjs-dist）でローカル表示する。Mainのattachments.preview(taskId, name)は既存添付サービスで通常ファイル・タスクID・単一ファイル名を検証し、50MB以下のPDFバイト列だけを返す。Rendererは任意パスへ直接アクセスしない。PDFヘッダーを検証し、破損・パスワード保護・欠損は理由と外部アプリ導線を表示する。PDFのスクリプト・添付・リンクは実行しない。Worker、CMap、日本語用フォントデータ、標準フォント、WASMを配布へ同梱し外部CDNを使わない。Electronのfile://ではWorkerを明示作成してPDF.jsへ渡し、CSPを緩和しない。

PowerPointはLibreOffice Impressのローカルheadless PDF変換を選択する。Microsoft Officeは不要。標準Program Files/Program Files (x86)配下のLibreOfficeを検出し、未導入なら導入要件を説明する。ppt/pptxに対応し、静止したスライドを同じPDFビューアで表示する。アニメーション・動画は再生せず、フォントやレイアウトの完全再現は保証しない。外部サービスへアップロードしない。

変換は資料のコピーとマクロセキュリティ最大の専用一時プロファイルを使い、元資料を開いて書き換えない。シェルを介さず引数配列で起動し、日本語・空白を含むパスを扱う。変換は1件ずつ、上限60秒。タイムアウト時は専用変換プロセスツリーを停止する。成功・失敗とも作成したcotaska-preview-一時フォルダのみ削除する。プロジェクト切替・添付取り外しの際に古い結果を表示しない。

ディスクの永続キャッシュは持たず、表示中のPDFだけメモリに保持する。再表示時は再変換し、閉じるとPDF.js文書・Workerを破棄する。強制終了時に残った一時フォルダはOS一時領域に残る場合がある。PDFは1ページずつ描画し、canvasの長辺4096px・画素比2以下に制限する。50MBは変換元・変換後の両方に適用する。大きすぎる資料は外部アプリで開く。

方式比較: Electron内蔵PDF表示は組込み・操作制御への依存が大きいためPDF.jsを採用した。PowerPoint COMはOffice必須でライセンス・自動化環境に依存する。pptxの独自解析は表示品質とppt対応が限定される。LibreOfficeは別途導入が必要だが、Office不要・両形式対応・ローカル処理を満たすため採用した。

参照: [PDF.js公式例](https://mozilla.github.io/pdf.js/examples/index.html)、[LibreOffice PDF CLI](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html)。

## Markdown画像とクリップボード（CHG-141）

詳細ペインと独立詳細ウィンドウの共通DetailPaneで実装する。画像を含むpasteイベントのみ通常貼り付けを止め、Mainの非同期clipboard.readとClipboardItem.getTypeで画像Blobを取得しnativeImageでPNGへ変換する（Electron 44対応、BUG-20261012-02）。画像取得中のプロジェクト変更は保存前に拒否する。attachments.pasteImage(taskId)は20MB以下の画像をattachments/image-時刻.pngへ排他保存し、同名は連番で回避する。旧形式タスクは既存のensureTaskFolderで個別移動する。全ウィンドウへ添付変更を通知する。

保存成功後に選択範囲を![Image](<attachments/ファイル名>)で置換する。保存中は本文編集と重複貼り付けを止める。保存失敗時は参照を挿入せずエラーを表示する。保存中に画面を離れた場合は本文挿入を行わず、保存画像は添付として保持する。通常テキスト貼り付けはブラウザ標準動作を維持する。

attachments.readImage(taskId, reference)は本文のフォルダを基準に相対画像を解決し、data URLを返す。日本語・空白・URLエンコードを扱う。タスク外への遡上、絶対パス、リンク、20MB超、非画像を拒否する。PNG/JPEG/GIF/WebP/BMP/SVG/ICO/AVIFに対応。HTTP(S)画像は通常のimg表示。画像はペイン幅以下・縦横比維持とし、欠損や読込失敗は代替テキストと理由を表示する。取り外し・復元の変更通知で再読込する。複製・バックアップは既存のタスク添付一式保存に含める。

## 保存

新規本文はtasks/T-ID/T-ID.md、添付は同階層のattachments/にコピー保存する。添付は本文からattachments/ファイル名で参照可能。旧形式本文は読み込み・更新・バックアップ復元を維持し、添付追加時にそのタスクだけIDフォルダへ移動する。一括移行は専用スキルに分離する。

添付フォルダは初回追加時に作成する。タスク探索と監視はattachments配下を除外する。UIは本文とは別に一覧と追加・開く・取り外し・復元を提供する。取り外した添付はattachments/.removed/の一意フォルダへ移し、同名があれば別名で復元する。上書き・実ファイルの永久削除を行わない。

## API

cotaskaAPI.attachmentsのlist(taskId)、add(taskId)、open(taskId, name)、remove(taskId, name)、restore(taskId, token)を提供。追加元はMainのファイル選択ダイアログで決定する。Rendererから任意の保存先パスを受け取らない。タスクIDはキャッシュから解決し、パス成分・シンボリックリンクを拒否する。変更後は全タスクウィンドウへattachments:changedを通知する。

## ライフサイクル

ゴミ箱では添付を保持する。タスク複製は添付（取り外し済みを含む）もコピーし、本文の相対リンクが維持される。アーカイブはarchive/T-ID/T-ID.mdとattachments.zip、その他のタスク内資料を保管する。既存の同名アーカイブは上書きせず停止する。

アーカイブ処理は一時保存先にタスクフォルダ全体をコピーしてから添付をZIP化し、各エントリのバイト内容を検証する。検証後に一時保存先の添付フォルダを除去し、正式アーカイブへ移す。元タスクの削除は最後に行い、圧縮・保存失敗時は元を保持する。本文は平文で検索可能。ZIP内の添付はOSのZIP閲覧で確認できる。

## バックアップと移行

既存のtasks/archive再帰バックアップに添付・取り外し済み資料・ZIPを含める。インデックスは保存せず復元後に生成。旧形式を自動一括移行しない。同期中のプロジェクトは全PCのアプリ・同期を停止し、対応版を揃えてから専用スキルで一か所だけ移行する。

大容量資料では現在の同期ZIP処理に時間・メモリが必要。圧縮済み画像・動画等の容量削減は保証しない。バックアップ先をtasks/archive配下に置くことを拒否し、バックアップ自身の混入を避ける。


## CHG-144 添付欄の配置と初期状態

添付欄はタスク詳細本文の下・関連サブタスクの上に配置する。初期状態とタスク切替時は折りたたむ。見出しに件数を表示し、クリックまたはキーボードで展開する。既存操作は展開時に表示する。通常詳細と独立詳細へ共通適用する。


## CHG-145 ドラッグ＆ドロップ

添付欄全体（折りたたみ見出しを含む）をドロップ先とする。preloadのwebUtils.getPathForFileでネイティブパスを取得し、attachments:addDroppedFiles IPCから既存add処理でコピー保存する。複数ファイルを受け付け、同名を上書きしない。通常ファイルだけを許可し、フォルダ・リンクを拒否する。readonlyと処理中はdropEffectをnoneとし、ブラウザのファイル表示への遷移を防ぐ。ドラッグ中はcopyと欄の強調を示す。ドロップ後は展開し、エラーも表示する。


## CHG-148 添付ファイル操作メニュー（従来の取り外し操作を置換）

取り外す・復元操作を廃止し、各ファイルの…メニューに外部アプリで開く、エクスプローラを開く、ファイルを削除するを表示する。エクスプローラでは該当ファイルを選択する。削除はshell.trashItemで添付コピーをOSごみ箱へ移し、成功後に一覧へ反映する。ゴミ箱内タスクは削除不可。本文リンクは自動変更しない。既存.removedの保管データは削除せずバックアップ対象として保持し、旧UI/IPCは公開しない。
