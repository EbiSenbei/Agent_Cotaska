# 99. その他機能

## 1. Cotaska.exe ランチャーの起動診断と確認付き自動復元（CHG-105）

### 1.1 目的と適用範囲

Portable 版のルート直下にある `Cotaska.exe` は、Electron 本体 `_app/CotaskaCore.exe` の起動前診断、起動直後の異常終了検知、および起動不能時の `_app` 専用復旧を担う。

通常起動では利用者へダイアログを表示せず、`CotaskaCore.exe` を起動する。異常を検出した場合だけ、原因、ログ、更新前バックアップ、および確認付き自動復元への導線を提供する。

### 1.2 責務境界

| 区分 | ランチャー復旧（CHG-105） | 設定画面のバックアップ・復元 |
|---|---|---|
| 目的 | アプリ本体の起動不能を復旧する | 利用者データを利用者操作で保全・復元する |
| 復元対象 | `_app/` のみ | タスク、リスト、設定 |
| 復元元 | `backup/portable-update-before-*.zip` | 利用者が選択したデータバックアップ ZIP |
| `data/` | 読み書きしない | バックアップ・復元対象 |
| `logs/`、`backup/` | 読み書き・削除しない。参照・表示のみ | バックアップ保存先として扱う |
| 実行契機 | 起動診断または起動直後の異常終了 | 設定画面での利用者操作 |

ランチャーはルートの `launcher.log` へ診断・復旧操作を追記する。これは `logs/` フォルダーの履歴を変更するものではない。

### 1.3 起動前診断

起動前に `_app/` 配下の次のファイルがすべて存在することを検査する。

- `CotaskaCore.exe`
- `icudtl.dat`
- `resources.pak`
- `snapshot_blob.bin`
- `v8_context_snapshot.bin`

不足が1つでもある場合、アプリ本体は起動しない。欠落したファイル名を `launcher.log` と復旧ダイアログへ記録・表示する。

### 1.4 起動直後の監視

必須ファイルがそろっている場合、ランチャーは `_app/CotaskaCore.exe` を `_app/` を作業ディレクトリとして起動する。起動後 10 秒間はプロセス継続を監視する。

- 10 秒を超えてプロセスが継続した場合は正常起動とみなし、ランチャーを終了する。
- 10 秒以内に終了した場合は異常終了として、終了コードと `_app/debug.log` の最新の `error` または `fatal` 行を復旧ダイアログに表示する。
- ウィンドウの表示有無は診断条件にしない。

### 1.5 復旧ダイアログ

異常時のモーダルダイアログは、検出内容、利用可能な更新前バックアップ、および「自動復元は `_app` のみを対象とし、利用者データを変更しない」ことを表示する。

| 操作 | 動作 |
|---|---|
| 自動復元へ進む | 復元確認を表示する。有効なバックアップがない場合は無効化する。 |
| バックアップを開く | `backup/` フォルダーをエクスプローラーで開く。 |
| エラーログを開く | `launcher.log` と、存在する場合は `_app/debug.log` を既定アプリで開く。 |
| 閉じる | 復元を実行せず終了する。 |

バックアップ候補は、`backup/portable-update-before-*.zip` のうち、ZIP 内の `_app` が必須ファイルをすべて持つ最新ファイルとする。旧 updater が残した同名ディレクトリは互換候補として扱う。候補がない、またはすべて無効な場合は、再配布パッケージからの手動復旧を案内する。

### 1.6 自動復元の状態遷移

```mermaid
stateDiagram-v2
    [*] --> 起動前診断
    起動前診断 --> 復旧ダイアログ: 必須ファイル不足
    起動前診断 --> 本体起動: 必須ファイルOK
    本体起動 --> 起動監視: CotaskaCore.exeを開始
    起動監視 --> 正常起動: 10秒継続
    起動監視 --> 復旧ダイアログ: 10秒以内に終了
    復旧ダイアログ --> 終了: 閉じる
    復旧ダイアログ --> 手動復旧案内: 有効バックアップなし
    手動復旧案内 --> 終了
    復旧ダイアログ --> 復元確認: 自動復元へ進む
    復元確認 --> 復旧ダイアログ: キャンセル
    復元確認 --> 同一ルートプロセス終了: 実行を確認
    同一ルートプロセス終了 --> 復旧失敗: 終了失敗
    同一ルートプロセス終了 --> 一時展開と検証: 終了成功または対象なし
    一時展開と検証 --> 復旧失敗: ZIP破損・必須ファイル不足
    一時展開と検証 --> _app退避と置換: 検証成功
    _app退避と置換 --> 復旧失敗: 置換・再検査失敗
    _app退避と置換 --> 復元完了: 再検査成功
    復旧失敗 --> 復旧ダイアログ: ログと退避物を保持
    復元完了 --> 本体起動: 起動を選択
    復元完了 --> 終了: 閉じる
    正常起動 --> [*]
    終了 --> [*]
```

### 1.7 確認付き復元と安全策

復元前に、復元元 ZIP、復元対象が `_app` のみであること、`data/`、`logs/`、`backup/` を変更しないことを明示して確認を求める。

同一 Portable ルート配下で実行中の `Cotaska.exe` または `CotaskaCore.exe` がある場合だけ、プロセス名と PID を表示する。利用者が確認した場合だけ終了を試みる。実行ファイルのパスが異なるインストール先の Cotaska プロセスは終了対象にしない。

復元は以下の順序で実行する。

1. ZIP を一時フォルダーへ展開する。旧形式のバックアップディレクトリは一時フォルダーへコピーする。
2. 展開・コピーした `_app` の必須ファイルを検査する。
3. 既存の `_app` を `_app.recovery-before-yyyyMMdd-HHmmss` へリネームして退避する。
4. 検査済みの `_app` だけを Portable ルートへ配置する。
5. 配置後に必須ファイルを再検査する。
6. 成功時は利用者が `Cotaska` を起動できるようにする。

置換または再検査に失敗した場合は、新しい `_app` を除去して退避済みの `_app` を戻す。バックアップ、`data/`、`logs/`、退避物は保持し、失敗理由を `launcher.log` に記録する。

### 1.8 更新前バックアップ

Portable updater は更新対象を置換する前に、`backup/portable-update-before-<timestamp>.zip` を作成する。ZIP には復旧対象の `_app` を含める。これは起動不能時のアプリ本体復旧用であり、利用者データのバックアップとは別のものである。

### 1.9 確認観点

- 必須ファイルがそろう通常起動ではダイアログを表示しない。
- 必須ファイルの欠落時、欠落名とログ・バックアップ導線を表示する。
- 起動後 10 秒以内の終了時、終了コードと最新エラーを表示する。
- 有効な更新前バックアップから `_app` だけを復元し、復元前後で `data/` の内容が変わらない。
- 同一ルートのプロセスだけが確認・終了対象となり、別インストール先のプロセスは対象外となる。
- ZIP破損、必須ファイル不足、ファイルロック時に、既存 `_app`、ログ、バックアップを保持する。

## 2. CotaskaUpdater.exe の更新中ダイアログ（CHG-106）

### 2.1 目的と適用範囲

Portable 版の更新では、Cotaska 本体の終了後に `tools/CotaskaUpdater.exe` が更新ファイルの展開、バックアップ、差し替え、再起動を実行する。この間は本体画面が存在しないため、updater は更新開始から再起動要求まで状態ダイアログを表示し、処理が継続中であり待機が必要なことを利用者へ知らせる。

本章は updater 単体の表示・更新処理・配布検証を対象とする。設定画面の更新確認・ダウンロード・利用者確認は `08_設定画面.md`、起動不能時のランチャー復旧は本書の CHG-105 を参照する。

### 2.2 責務境界

| 区分 | CotaskaUpdater.exe（CHG-106） | Cotaska.exe ランチャー（CHG-105） | 設定画面 |
|---|---|---|---|
| 実行契機 | 更新を確定して Cotaska 本体を終了した後 | 通常起動時・起動失敗時 | 本体起動中の利用者操作 |
| 主な責務 | 更新、更新前バックアップ、状態通知、再起動 | 起動診断と `_app` の復旧 | 更新確認、ダウンロード、更新開始確認 |
| UI | 更新中の操作不可ダイアログ、失敗時のエラー表示 | 異常時だけの復旧ダイアログ | 更新操作・準備状態の表示 |
| `data/`、`logs/`、`backup/` | 上書きしない。`logs/` へ更新ログ、`backup/` へ更新前バックアップを追加する | 変更・削除しない | 利用者データの明示的なバックアップ・復元を扱う |

### 2.3 起動条件と処理順

main process はダウンロード・検証済みの `Cotaska-Portable.zip`、Portable ルート、更新バージョンを引数に `CotaskaUpdater.exe` を detached 起動し、その後 Cotaska 本体を終了する。updater は次の順に処理する。

1. 状態ダイアログを表示する。
2. 同一 Portable ルートの Cotaska 関連プロセスの終了を待つ。
3. 更新 ZIP を一時フォルダーへ展開し、`Cotaska-Portable/` と必須ファイルを検証する。
4. 更新対象を一時バックアップへ複写し、`backup/portable-update-before-<timestamp>.zip` を作成する。
5. `Cotaska.exe`、`_app/`、`tools/`、配布ドキュメントを差し替える。
6. `Cotaska.exe` の再起動を要求し、完了を短時間表示してダイアログを閉じる。

更新対象に `data/`、`logs/`、`backup/`、利用者が置いた任意ファイルは含めない。

### 2.4 状態ダイアログ

ダイアログのタイトルは `Cotaska を更新しています` とする。常に前面へ表示し、不確定進捗バーと「このウィンドウは更新完了後に自動で閉じます。」の注意文を表示する。処理件数と所要時間は環境により変動するため、百分率は表示しない。

| 処理段階 | 表示メッセージ |
|---|---|
| 起動 | `更新を開始しています...` |
| 本体終了待機 | `Cotaska の終了を待っています...` |
| ZIP展開 | `更新ファイルを展開しています...` |
| 内容検証 | `更新内容を確認しています...` |
| 更新前バックアップ | `現在のファイルをバックアップしています...` |
| 差し替え | `アプリを差し替えています...` |
| 再起動 | `Cotaska を再起動しています...` |
| 成功 | `更新が完了しました。` |
| 失敗時の復元 | `バックアップから復元しています...` |

利用者による閉じる、最小化、最大化は許可しない。成功時は再起動要求後に自動で閉じる。ダイアログ自体の生成・更新に失敗した場合も、更新処理、ログ出力、失敗時の復元は継続する。

### 2.5 失敗時の扱い

更新処理が失敗した場合は、利用可能な更新前バックアップから復元を試みる。状態ダイアログを閉じた後、既存のエラーダイアログで失敗理由を表示する。ログは updater の作業場所と Portable ルートの `logs/portable-update-<timestamp>.log` に出力し、利用者は後者を参照できる。

### 2.6 配布と検証

`20_app/setup/updater/build.ps1` は `UpdaterFallback.cs` から `20_app/scripts/CotaskaUpdater.exe` を生成する。`release-all.ps1` は updater のビルドに失敗した場合はリリースを中止し、配布フォルダーの `tools/CotaskaUpdater.exe` と `Cotaska-Portable.zip` 内の `Cotaska-Portable/tools/CotaskaUpdater.exe` がビルド成果物と SHA-256 で一致することを検証する。

### 2.7 確認観点

- 更新開始から Cotaska の再起動要求まで、状態ダイアログが表示され続ける。
- 各処理段階で対応するメッセージが表示され、利用者がウィンドウを閉じられない。
- 更新 ZIP 不正またはファイルロック時に、復元中メッセージ、エラー表示、`logs/portable-update-*.log` を確認できる。
- ダイアログ表示に失敗しても、更新ログとエラー・復元処理が継続する。
- Portable 配布 ZIP にダイアログ対応済みの `tools/CotaskaUpdater.exe` が含まれる。
