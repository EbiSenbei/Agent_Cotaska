# 基本設計 - AI連携

## 1. 概要

Cotaska から Codex SDK を呼び出し、AIチャット上でタスク情報の参照、相談、更新提案、利用者承認後の反映を行う仕組みを提供する。

CHG-058 の対象は Codex SDK のみとする。GitHub Copilot CLI、Claude Code、Gemini CLI などの外部CLIプロバイダ追加や複数プロバイダ選択は対象外とする。

Codex SDK の応答にタスク更新やファイル更新の提案が含まれる場合、自然文を直接タスク正本へ反映しない。Cotaska が検証可能な構造化アクションとして扱い、利用者承認後に既存サービス層を通じて反映する。

**アーキテクチャ（2026-03-18 改訂）**：
- タスクが個別Markdownファイルなため、AIが直接ファイルを読み書き可能
- `_index.yaml` で高速なタスク一覧取得を実現
- `fs.watch` + watcher.js でリアルタイム双方向同期
- Markdown本文をAIが直接編集するため、「Markdown出力」は達成済み

**CHG-058 追加アーキテクチャ（2026-05-14 改訂）**：
- renderer は preload bridge / IPC 経由で main process に AI 操作を依頼する
- main process は Codex SDK を呼び出し、Codex SDK 側の `threadId` を Cotaska 側AIスレッドへ紐づける
- AIスレッド、チャット履歴、参照ファイル、Codex実行ログ、タスク更新提案、承認/却下/反映履歴は `data/ai.sqlite` に保存する
- タスク正本は引き続き `data/tasks/*.md` とし、承認済みのタスク変更だけを `taskService` 経由で反映する
- `_index.yaml` は引き続き生成物であり、AI連携でも直接編集しない
- OpenAI APIキー、Codex access token、ChatGPTログイン情報、`~/.codex/auth.json` の内容は Cotaska に保存しない

## 1.1 CHG-058 の設計原則

| 項目 | 方針 |
|------|------|
| 連携対象 | Codex SDK のみ |
| 対象外 | GitHub Copilot CLI / Claude Code / Gemini CLI / 複数AI CLIプロバイダ方式 |
| SDK呼び出し | Electron main process から実行する |
| renderer | Codex SDK を直接呼び出さず、preload bridge の IPC だけを使う |
| 認証 | Codex SDK / ローカルCodex実行環境の認証状態を利用し、Cotaska に認証情報を保存しない |
| 作業フォルダ | 設定画面で指定する。初期値は空欄。ユーザーが明示的に選択した場合のみ保存する |
| 実行権限 | 設定画面で変更可能。初期値は `read-only`。`workspace-write` / `danger-full-access` も選択可能 |
| 反映方式 | AI提案をプレビューし、利用者承認後に Cotaska 側で反映する |
| 正本 | タスクは `data/tasks/*.md`、AI関連履歴は `data/ai.sqlite` |

## 1.2 AI画面構成

AI画面は通常のタスク詳細ペインの一部ではなく、サイドバーのAIアイコンから開く独立した作業画面とする。

```text
┌────────┬────────────────────┬───────────────────────┬──────────────────────┐
│サイドバー│ AIスレッド/ファイル │ AIチャット              │ タスク/ファイル/差分   │
│         │ 切り替えペイン       │                       │ プレビュー（任意表示） │
└────────┴────────────────────┴───────────────────────┴──────────────────────┘
```

| 領域 | 責務 |
|------|------|
| 左端サイドバー | リスト、検索、AI、設定などの主要画面切り替え |
| AIスレッド/ファイル切り替えペイン | Cotaska 側AIスレッド一覧、参照ファイルツリー、対象タスク候補を表示 |
| AIチャット | ユーザー入力、Codex SDK 応答、実行状態、エラー、タスク更新提案を表示 |
| 右プレビュー | 関連タスク、参照ファイル、差分、承認前プレビューを必要時に表示 |

### 1.2.1 AI画面の操作仕様

AI画面は、Codex / ChatGPT に近い「左に会話や参照の一覧、中央にチャット、右に必要時だけ詳細」を基本とする。

| 対象 | 仕様 |
|------|------|
| AIアイコン | 左端サイドバーでは検索アイコンの直下に配置し、他アイコンと同じ見た目にする |
| AIスレッド一覧 | Cotaska 側で管理するスレッドを表示する。Codex SDK 側の `threadId` は外部実行IDとして紐づける |
| スレッドアーカイブ | スレッド行にアーカイブ操作を表示し、アーカイブ済みスレッドは通常一覧から除外する。会話履歴や提案履歴は保持する |
| ファイルツリー | AIスレッド一覧と同じ左ペイン内でタブ等により切り替える。VS Code の Explorer に近い階層表示とし、初期状態ではフォルダを折りたたむ |
| ファイルツリーの右クリック | ファイルまたはフォルダに対して「パスをコピー」「エクスプローラで表示する」「削除」を表示する。削除は確認を挟み、作業フォルダ外や危険な対象を拒否する |
| 参照ファイル追加 | チャット入力欄左下の `+` ボタンからファイル選択を行う。参照ファイル表示は入力欄内に集約し、チャット上部には重複表示しない |
| 参照ファイル表示 | 入力欄内に添付チップとして表示し、不要な参照は送信前に外せるようにする |
| 権限変更 | チャット入力欄内で現在の権限を表示し、送信前に一時的に変更できる。設定画面の保存値とは区別する |
| 送信ボタン | チャット入力欄右下に送信ボタンを置き、空入力や送信中は無効化する |
| メッセージ操作 | メッセージにマウスカーソルを当てた時だけ投稿日時と本文コピーボタンを表示する |
| 最下部へ移動 | チャット途中をスクロールして最下部から離れた場合、入力欄直上中央付近に下向きボタンを表示し、押下で最新メッセージへ移動する |
| タスクIDリンク | チャット本文中の `T-XXXX` はリンク風に表示し、クリック時は右プレビューに対象タスク詳細を表示する |
| Markdownローカルリンク | AIチャット本文および右プレビュー内のMarkdownプレビューからローカルファイルリンクを開く場合、main process が `file://`、相対パス、URLエンコード、行番号サフィックスを正規化・存在確認して右プレビューへ渡す。`T-XXXX.md` はタスク詳細、テキスト/Markdown/PDFは既存ファイルプレビューで表示する（CHG-092） |
| Markdown外部リンク | `http://` / `https://` は main process 経由で既定ブラウザへ開く。その他の未解決・未対応リンクはメイン画面を遷移させず、右プレビューにエラーを表示する（CHG-092） |
| Markdown表示 | AI応答内のMarkdownテーブルは罫線付きで表示する |

右プレビューは常時表示する情報パネルではなく、タスクリンク、ファイルツリーのファイルクリック、チャット本文のローカルMarkdownリンク、差分や承認前プレビューなど、利用者が確認対象を明示した時に開く補助ビューとする。相対リンクは、右プレビュー内のMarkdownでは表示中ファイルの親ディレクトリ、AIチャット本文では設定済み作業フォルダを基準に解決する。スレッド概要や提案カードだけを表示するための「コンテキストパネルを開く」ボタンは置かない。

画面モックは `10_docs/10_設計/30_画面モック/ai_chat_codex_sdk_mock.html` を正とする。

## 1.3 Codex SDK 実行フロー

```text
Renderer
  │ window.cotaskaAPI.aiChat.sendMessage(...)
  ▼
Preload bridge
  ▼
Main process aiService
  │ 認証状態確認 / 作業フォルダ確認 / 参照ファイル上限確認
  ▼
Codex SDK
  │ 応答 / threadId / 実行ログ / エラー
  ▼
aiStorage(data/ai.sqlite)
  │ スレッド・メッセージ・提案・実行ログを保存
  ▼
Renderer
  │ チャット表示 / 提案プレビュー / 承認操作
  ▼
taskService または fileService 相当
  │ 承認済みアクションのみ反映
  ▼
data/tasks/*.md または許可された作業フォルダ配下ファイル
```

Codex SDK 実行前に、Cotaska は必要に応じて認証状態を確認する。未認証、期限切れ、SDK未検出、実行失敗の場合は、Cotaska 内へAPIキー入力を促さず、Codex 側でのログインや環境確認を案内する。

### 1.3.1 ストリーミング表示

現行実装では、Codex SDK の `runStreamed()` から受け取る途中イベントを main process から renderer へ通知し、処理中だけ一時的な進行状況として時系列に表示する。最終応答はチャットへ保存・表示する。

| 項目 | 方針 |
|------|------|
| IPC | `invoke` の戻り値だけでなく、購読型APIまたは `webContents.send` 相当で途中イベントを通知する |
| renderer表示 | 生成中は処理途中イベントを時系列で下方向へ累積表示する。イベント受信ごとの上書き表示は行わない |
| バックグラウンド継続 | Codex SDK 実行は renderer の表示ライフサイクルに依存させず main process 側の実行単位として管理する。AI画面から離れても明示的な中断操作がない限り `runStreamed()` をキャンセルしない（CHG-094） |
| 実行中スレッド表示 | AIスレッド一覧では、`ai_runs` または main process のアクティブ実行状態から処理中スレッドを判定し、該当スレッド行の右端にアニメーションする処理中アイコンを表示する（CHG-094） |
| コマンドライン詳細 | `command_execution` イベントの実行コマンド、stdout、stderr は「コマンドライン詳細」として初期状態を折り畳む。通常の途中経過メッセージ、推論、ファイル変更、ツール実行は展開したまま表示する |
| 途中経過の優先度 | `agent_message` と `reasoning` はMarkdown・段落を生かした本文表示として累積し、コマンド実行は小さな実施記録だけを常時表示する。コマンドの実行内容・stdout・stderr は「詳細を表示」を開いたときだけ表示する（CHG-093） |
| 保存対象 | DBの正本は最終応答とし、途中断片はチャット履歴へ保存しない。ただし実行中の画面復帰に備え、main process 側で処理中イベントを短期キャッシュする（CHG-094） |
| 途中イベント復元 | 画面復帰またはスレッド再選択時、renderer はアクティブ実行一覧と短期キャッシュ済み途中イベントを取得し、処理中表示を復元する。キャッシュは実行中のみ最大件数を制限して保持し、完了・失敗・中断後は最終メッセージまたはエラーメッセージを正本として表示する |
| フォールバック | ストリーミング未対応または失敗時は、従来どおり最終応答の一括表示へ戻す |
| 最終応答時 | 最終応答が確定したタイミングで処理途中イベントを一括クリアし、通常の assistant メッセージとして最終応答だけを表示する |
| エラー/キャンセル | UIが待機状態のまま残らないよう、実行状態を必ず失敗またはキャンセルへ遷移させる。途中イベントは待機表示として残さず、エラーまたは中断メッセージへ置換する |

処理途中イベントは、ユーザーが実行中の流れを追うための一時表示であり、チャット履歴の正本には含めない。長時間処理では複数イベントが下方向へ追加され、最新イベントへ追従できるようスクロールを要求する。`command_execution` の詳細ログだけは初期状態を閉じ、利用者がイベントごとに展開して確認できる。展開状態は同じ実行中に新規イベントが追加されても維持する。画面遷移後にAI画面へ戻った場合は、main process 側のアクティブ実行と短期キャッシュ済み途中イベントから処理中表示を復元する。完了後の画面では途中経過が残り続けず、ユーザー発言と最終回答を中心に読める状態に戻す。

## 1.4 許可アクション

Codex SDK の応答から Cotaska が反映対象として扱う構造化アクションは、以下に限定する。

| action_type | 対象 | 反映先 | 方針 |
|-------------|------|--------|------|
| `update_task` | 既存タスク | `data/tasks/*.md` | 既存 `taskService.updateTask` / `updateTaskContent` 相当を通す |
| `create_task` | 新規タスク | `data/tasks/*.md` | 既存 `taskService.addTask` 相当を通す |
| `update_file` | 作業フォルダ配下の許可ファイル | 対象ファイル | 差分プレビューと承認後に Cotaska 側で書き込む |

共通ルール:

- 利用者承認前にタスクファイルや作業ファイルへ反映しない
- `update_task` / `create_task` は既存のタスク入力検証、frontmatter 検証、ID採番ルールに従う
- `update_file` は設定された作業フォルダ配下のみ許可する
- `_index.yaml`、認証情報、生成物、アプリ実行バイナリ、履歴削除に関わる変更は拒否する
- 構造化できない自然文提案はチャット表示に留め、反映ボタンを出さない
- 不正なタスクID、存在しない対象、許可外フィールド、YAML破損を招く内容は承認前検証で拒否する

### 1.4.1 アクション提案の自動抽出（後続拡張）

Codex SDK 応答から `update_task` / `create_task` / `update_file` の提案を自動抽出する処理は、基盤実装後の拡張として扱う。抽出できない通常会話はチャット履歴として保存し、提案扱いにしない。

| 項目 | 方針 |
|------|------|
| 抽出形式 | Codex へ機械的に抽出しやすいJSONブロック等の形式を促す |
| 登録先 | 検証済み提案のみ `ai_action_proposals` へ登録する |
| 事前検証 | `action_type`、対象タスクID/ファイルパス、payload構造、許可フィールド、作業フォルダ配下判定を行う |
| 失敗時 | 抽出失敗や不正payloadはチャット送受信失敗にせず、提案未登録または警告として扱う |
| 承認UI | 自動抽出後も、利用者承認前にはタスク正本や作業ファイルへ反映しない |

## 1.5 AI関連データ保存

AI関連データの正本は SQLite とし、ファイルは `data/ai.sqlite` に配置する。

タスク本体や設計ドキュメントの正本は従来どおり Markdown / YAML で管理する。AIチャット履歴は通常運用では Markdown へ逐次保存しない。必要な場合のみエクスポートまたは要約として出力する。

| データ | 保存先 |
|--------|--------|
| タスク本文・frontmatter | Markdown (`data/tasks/*.md`) |
| タスク一覧インデックス | YAML生成物 (`data/tasks/_index.yaml`) |
| AIスレッド | SQLite (`data/ai.sqlite`) |
| AIチャット履歴 | SQLite (`data/ai.sqlite`) |
| Codex SDK 側 `threadId` | SQLite (`data/ai.sqlite`) |
| 参照ファイル一覧 | SQLite (`data/ai.sqlite`) |
| Codex実行ログ | SQLite (`data/ai.sqlite`) |
| タスク更新提案 | SQLite (`data/ai.sqlite`) |
| 承認/却下/反映履歴 | SQLite (`data/ai.sqlite`) |
| 承認済みタスク変更 | Markdown (`data/tasks/*.md`) |
| 重要な技術判断 | Markdown / `00_mgmt/DECISIONS.md` |

## 1.7 作業フォルダ・参照ファイル

設定画面で Codex SDK の作業フォルダを指定できるようにする。初期値は空欄とし、ユーザーが明示的に選択した場合のみ保存する。

| 項目 | 方針 |
|------|------|
| 作業フォルダ | 設定画面で指定。初期値は空欄。ユーザーが明示的に選択した場合のみ保存 |
| ファイルツリー | 設定された作業フォルダ配下を表示 |
| 参照ファイル上限 | 初期値は最大10件 |
| 合計文字数上限 | 初期値は100,000文字 |
| 上限超過時 | 送信前に表示し、参照対象を調整できるようにする |
| 書き込み | `update_file` の承認後のみ、作業フォルダ配下へ Cotaska 側で反映 |

作業フォルダが未設定の場合、AIモード起動時またはファイルツリー表示時に警告を表示する。警告では設定画面で作業フォルダを指定する必要があることを案内し、存在しないパスやアクセスできないパスを通常のファイルツリーとして扱わない。

参照ファイルは、ドラッグ&ドロップまたはファイル選択で追加できる。作業フォルダ外のファイルも参照ファイルとして扱えるが、Cotaska 内へ一時コピーしない。Codex SDK へ渡すために必要な読み取りは main process 側で行い、送信時の参照上限と存在確認を必ず適用する。

ファイルツリーでテキストファイルをクリックした場合、右プレビューの表示領域をできるだけ広く使って内容を表示する。表示は読み取り専用を基本とし、編集は構造化提案または将来仕様として扱う。Markdownファイルの場合はプレビュー切り替えを提供し、任意のファイルは外部アプリで開けるようにする。

## 1.8 認証情報の扱い

Cotaska は Codex SDK / ローカルCodex実行環境の認証状態を利用するが、認証情報そのものを保存しない。

保存しない情報:

- OpenAI APIキー
- Codex access token
- ChatGPTログイン情報
- `~/.codex/auth.json` の内容

Cotaska が扱ってよい情報:

- 認証状態（利用可能 / ログイン必要 / 期限切れ / SDK未検出 / エラー）
- 認証方式の表示名
- 最終確認日時
- 診断用エラーメッセージ
- 必要に応じた `CODEX_HOME` の参照パス

設定画面にAPIキー入力欄は置かない。未認証または期限切れの場合は、Codex 側でのログインを案内する。

### 1.8.1 CHG-058 現行実装の補足

T-0355〜T-0357、および応答速度改善系タスクの反映として、AI連携の現行仕様を以下に整理する。

#### 認証状態確認

- 認証確認は renderer から `window.cotaskaAPI.aiChat.checkAuthStatus()` を呼び、main process 側で実行する。
- main process は `@openai/codex-sdk` 同梱の Codex CLI を解決し、`doctor --json` を実行して認証状態を判定する。
- renderer へ返す状態は `available` / `login_required` / `expired_possible` / `sdk_missing` / `cli_unavailable` / `error` の安全な区分に変換する。
- Cotaska は OpenAI APIキー、Codex access token、ChatGPTログイン情報、`~/.codex/auth.json` の内容、`doctor --json` の生JSONを保存・表示・複製しない。
- AIチャット実行時に認証エラーを検出した場合は、チャット上で「設定で確認」できる導線を表示し、設定画面の Codex 認証状態確認へ誘導する。

#### ストリーミング表示

- ストリーミング表示は後続拡張ではなく実装済みとして扱う。
- Codex SDK の `runStreamed()` を main process から呼び、`aiChat:runEvent` で renderer へ途中イベントを通知する。
- renderer は生成中の途中イベントを一時表示し、イベント受信ごとに下方向へ累積する。生成中 assistant メッセージの本文上書き表示は行わない。
- DBへ保存する `ai_messages` の正本は最終応答とし、途中断片はチャット履歴へ保存しない。実行中の画面復帰用に、main process は途中イベントを短期キャッシュし、renderer はアクティブ実行一覧とイベントキャッシュを取得して表示を復元できる。
- AIスレッド一覧では、処理中のスレッド行の右端にアニメーションする処理中アイコンを表示する。完了・失敗・中断によりアクティブ実行から外れたらアイコンを消す。
- 最終応答が確定したら、途中イベント表示を一括クリアし、保存済みの最終応答を通常の assistant メッセージとして表示する。
- ストリーミング未対応または失敗時は、従来どおり最終応答の一括表示へフォールバックする。

#### AI速度とCodexスレッド戦略

- 設定値 `aiChat.performanceMode` は `standard` / `speed` を持つ。
- `standard` は会話継続性を優先し、Cotaska AIスレッドに紐づく Codex SDK 側 `threadId` を継続利用する。
- `speed` は応答速度を優先し、軽量Codex実行プロファイルを使う。
  - `web_search_mode`: `disabled`
  - `multi_agent_enabled`: `false`
  - `model_reasoning_effort`: `low`
  - `service_tier`: 可能な場合は高速寄り
- `minimal` 相当のプロファイルは Codex SDK 側の互換性エラーが確認されたため、現時点では使用しない。
- `speed` では既存の Codex SDK 側 `threadId` を継続せず、短命の Codex スレッドとして実行する。Cotaska 側のAIスレッド、チャット履歴、参照ファイル、実行履歴は維持する。
- `speed` 実行時に得た Codex SDK 側 `threadId` は `ai_runs.codex_thread_id` に記録するが、`ai_threads.codex_thread_id` は上書きしない。
- この方式は既存の `ai_runs.codex_thread_id` で追跡可能なため、DBテーブル追加は不要とする。

#### AI診断ログ

- 設定値 `aiChat.diagnosticsEnabled` は既定OFFとする。
- ONの場合のみ、応答時間、初回イベントまでの時間、最初のAI本文までの時間、トークン数、キャッシュトークン数、performance mode、Codexスレッド戦略をログへ出力する。
- 診断ログにはユーザー入力本文、AI応答全文、認証情報、アクセストークン、`auth.json` の内容を出力しない。

## 3. AI連携の中核：双方向同期

### 3.1 データフロー

```
┌─ AIエージェント（VSCode）────────┐
│                                    │
│ 30_data/tasks/ の .md ファイルを    │
│ 直接編集（frontmatter + 本文）      │
│                                    │
└────────────┬──────────────────────┘
             │ fs.writeFileSync()
             ▼
   30_data/tasks/T-XXX.md（更新）
             │
             ├─→ watcher.js 検知
             │    (chokidar)
             │
             ▼
   taskService.js → キャッシュ更新
             │
             ├─→ indexService.js
             │    (_index.yaml 再生成)
             │
             ▼
   win.webContents.send('tasks:changed')
             │
             ▼
┌─ Renderer プロセス（UI）───────────┐
│                                     │
│ tasks:changed イベント受信           │
│  → tasks:getAll 呼び出し            │
│  → リスト表示をリアルタイム更新       │
│                                     │
└─────────────────────────────────────┘
```

### 3.2 処理フロー（詳細）

1. **AIがファイルを編集**
   ```markdown
   # 30_data/tasks/T-001.md
   ---
   status: doing → blocked  # 変更
   progress_status: 未着 → 仕掛  # 変更
   ---
   タスク本文の編集...
   ```

2. **watcher が検知**（chokidar）
   - ファイル変更イベントを捕捉
   - taskService に通知

3. **キャッシュ更新**
   - taskService が新ファイルを読み込み
   - メモリキャッシュを更新

4. **インデックス再生成**
   - indexService が `_index.yaml` を上書き
   - タスク一覧のスナップショット保存

5. **UI通知**
   - `tasks:changed` を renderer に送信
   - renderer が自動的に `tasks:getAll` を呼び出し
   - 画面のタスク一覧がリアルタイム更新

## 4. アクセス方法

### 4.1 AIがタスク情報を読み取る

**高速読み取り（推奨）**：
```yaml
# 30_data/tasks/_index.yaml（自動生成・読み取り専用）
tasks:
  - id: T-001
    title: タスク名
    status: todo
    priority: high
    due_date: 2026-03-20
    list: リスト名
    created_at: 2026-03-18T10:00:00
  - id: T-002
    ...
last_updated: 2026-03-18T15:30:00
next_task_id: 1000
```

**詳細読み取り**：
```markdown
# 30_data/tasks/T-001.md（フルデータ）
---
id: T-001
title: ...
...（全frontmatter）
---
Markdown本文...
```

### 4.2 AIがタスク情報を書き込む

**推奨方法**：frontmatter + 本文を編集
```markdown
---
id: T-001
title: 修正後のタスク名
status: doing
progress_status: 仕掛
updated_at: 2026-03-18T16:00:00
---

修正後の本文内容

- 詳細な記述
- チェックリスト
```

**禁止事項**：
- `_index.yaml` の直接編集（自動上書きされる）
- `id` フィールドの変更（タスク識別ができなくなる）
- ファイル名を T-XXX.md 形式以外に変更

## 9.5 CHG-058 テスト観点

- Codex SDK のみが連携対象であり、複数AI CLIプロバイダ選択が表示されないこと
- サイドバーのAIアイコンからAI作業画面を開けること
- AI画面が `[サイドバー][AIスレッド/ファイル][チャット][右プレビュー]` の構成になっていること
- Cotaska 側AIスレッドと Codex SDK 側 `threadId` を紐づけて保存できること
- AIスレッド、チャット履歴、参照ファイル、実行ログ、提案、承認履歴が `data/ai.sqlite` に保存されること
- タスク正本は `data/tasks/*.md` のままで、`_index.yaml` を直接編集しないこと
- OpenAI APIキー、Codex access token、ChatGPTログイン情報、`~/.codex/auth.json` の内容を Cotaska に保存しないこと
- 未認証または期限切れの場合、Cotaska 内にAPIキー入力を促さず、Codex 側ログイン案内を表示すること
- 設定された作業フォルダ配下だけを参照/更新対象にすること
- 参照ファイル上限（最大10件、合計100,000文字）超過時に送信前に調整できること
- `update_task` / `create_task` / `update_file` 以外の提案は反映対象にしないこと
- 承認前にタスクファイルや作業ファイルが変更されないこと
- 承認済みの `update_task` / `create_task` は既存 `taskService` 経由で反映されること
- `update_file` は差分プレビュー後、承認済みかつ作業フォルダ配下の場合のみ反映されること
