# CHG-082 タスク表示性能改善

## 概要

タスク件数が増えた場合の起動後操作、外部編集反映、検索、一覧表示の体感速度を改善する。

## 背景

現在のファイル監視ではタスクファイル変更のたびに全タスクキャッシュを再構築し、`_index.yaml` を即時再生成して renderer へ全件通知している。大量タスク運用では、連続保存や同期ツールによる複数変更時に I/O と描画負荷が集中しやすい。

## 変更内容

- タスクファイル監視時は、変更対象ファイルのみ `taskService` のメモリキャッシュへ反映する。
- `_index.yaml` の再生成と renderer 通知は、短時間の変更をまとめて batch 実行する。
- renderer の通常・検索などのフラット一覧は、多件数時に表示範囲のみ描画する。
- 検索判定はタスク変換時に軽量な検索テキストを作成し、検索ごとの配列再生成を避ける。

## 受け入れ条件

- タスクファイル1件の変更で全ファイル再読み込みが発生しない。
- 連続した複数ファイル変更で `_index.yaml` 再生成と renderer 通知がまとめて実行される。
- 多件数のフラット一覧で DOM 描画対象が表示範囲中心に制限される。
- 検索結果が従来と同じ条件で一致する。
- `npm run build` が成功する。

## 実装結果

- `taskService.applyFileChange()` を追加し、add/change/unlink をファイル単位でキャッシュへ反映するようにした。
- `watcher.js` は変更イベントを 250ms debounce し、`indexService.rebuildIndex()` と `tasks:changed` 通知を batch 実行するようにした。
- `MainPane` のフラット一覧は 120 行超で仮想化し、スクロール範囲周辺のみ描画するようにした。
- renderer の検索は `mapFileTask()` 時に `searchText` を作り、検索時は文字列包含判定だけを行うようにした。
