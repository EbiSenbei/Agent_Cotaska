## 変更ID

CHG-058

## 変更内容

CotaskaにCodex SDKを使ったAIチャット連携機能を追加する。

CHG-058の対象はCodex SDKのみとし、GitHub Copilot CLI、Claude Code、Gemini CLIなどの別CLIプロバイダ追加は本変更の範囲外とする。

Codex SDKの応答にタスク更新提案が含まれる場合は、自然文を直接反映せず、Cotaskaが検証可能な構造化アクションとして扱う。ユーザー承認後に既存のタスクAPIを通じて `data/tasks/*.md` に反映する。

## 変更理由

Cotaska上でタスクを見ながらCodexへ相談し、返答や提案を同じ作業画面で確認できるようにするため。CLIプロセスの個別起動や複数プロバイダ抽象を初期仕様に含めると実装範囲が広がるため、まずはCodex SDKだけを公式連携手段として扱い、スレッド管理・継続実行・サンドボックス指定をSDK側の機能に寄せる。

## 影響範囲

- UI: AIチャットペイン、Codex SDK接続状態表示、送信欄、応答表示、操作提案プレビュー、承認/却下操作を追加する。
- API/IPC: rendererからmain processへCodex SDK実行を依頼するIPCを追加する。
- main process: Codex SDK呼び出し、スレッド開始/継続/再開、結果ログ保存、構造化アクション検証を追加する。
- タスクデータ: 承認済みアクションのみ既存の `taskService` 経由で `data/tasks/*.md` を更新する。
- AIデータ: AIスレッド、チャット履歴、参照ファイル、実行ログ、タスク更新提案、承認/却下履歴をSQLiteに保存する。
- 認証: Cotaska内にOpenAI APIキーを独自保存しない。Codex SDK/ローカルCodex実行環境側の認証状態を利用する前提とする。

## 対象連携方式

- Codex SDKのみ

## Codex SDK設定初期方針

- 作業フォルダ: Cotaska リポジトリルート
- 権限: 設定画面で変更可能。初期値は読み取り専用
- タスク編集方式: 承認後にCotaskaが反映
- 認証: Cotaska内にはAPIキーを保存しない

## Codex SDK認証・セッション備忘録

- Cotaska起動のたびにユーザーへCodex認証を求める仕様にはしない。
- 初回または認証切れの場合のみ、ユーザーにCodex側でのログインを促す。
- Codexの認証情報はCodex CLI/SDK側のローカル環境に保持される前提とする。
  - ChatGPTログインセッションは、OS資格情報ストアまたは `~/.codex/auth.json` に保存される。
  - OpenAI APIキー、Codex access token、ChatGPTログイン情報はCotaska内に保存しない。
  - `~/.codex/auth.json` は秘密情報として扱い、Cotaskaが内容を表示・複製・管理しない。
- Cotaskaは秘密情報ではなく、認証状態と診断情報のみを扱う。
  - 認証状態: `利用可能` / `ログイン必要` / `期限切れ` / `SDK未検出` / `エラー`
  - 認証方式表示: `ChatGPTログイン` / `APIキー` / `不明`
  - 最終確認日時
  - 必要に応じて `CODEX_HOME` の参照パス
  - 診断用のエラー内容またはログ参照先
- Cotaskaの設定画面にはAPIキー入力欄を置かない。
- Cotaskaの設定画面には、認証状態表示、認証状態の再確認、Codexログイン案内、診断ログ参照を置く。
- CotaskaからCodex SDKを呼び出す前に、必要に応じて認証状態を確認し、未認証または期限切れの場合は処理を中断してユーザーへ再ログインを案内する。

## AI画面構成方針

- AI画面はタスク詳細の一部ではなく、独立したAI作業画面として扱う。
- 基本構成は `[左アイコン] [スレッド/ファイル切替] [チャット] [タスク/ファイル/差分ビュー]` とする。
- 左アイコンメニューのAIアイコンは検索アイコンの一つ下に配置する。
- 2列目は `AIスレッド一覧` と `ファイルツリー` をタブ等で切り替えられるようにする。
- 中央はAIとのチャットを主役にする。
- 右ペインは必要時だけ開く補助ビューとし、関連タスク、参照ファイル、差分、承認前プレビューを表示する。
- 右ペインは、タスクリンク押下、ファイルツリーのファイル押下、差分確認など利用者が確認対象を指定した場合に開く。スレッド概要や提案カードだけを表示するための「コンテキストパネルを開く」ボタンは置かない。
- チャット入力欄には `+` による参照ファイル追加、権限変更、送信ボタンを集約する。参照ファイルのチップ表示も入力欄内に置き、チャット上部には重複表示しない。
- メッセージにマウスカーソルを当てた場合、投稿日時と本文コピーボタンを表示する。
- チャット本文中の `T-XXXX` はタスクリンクとして扱い、クリック時は右ペインにリストモードのタスク詳細相当を表示する。
- チャット途中をスクロールして最下部から離れた場合、入力欄直上に最下部へ戻るボタンを表示する。
- Markdownテーブルは罫線付きで表示する。
- ファイルツリーはVS Code Explorerに近い階層表示とし、初期状態ではフォルダを折りたたむ。ファイル/フォルダの右クリックでは「パスをコピー」「エクスプローラで表示する」「削除」を扱う。
- テキストファイルは右ペイン全体を使って読み取り専用表示する。Markdownファイルはプレビュー切替を提供し、ファイルは外部アプリで開けるようにする。

## AIスレッド管理方針

- 画面左のAIスレッド一覧はCotaska側で管理する。
- Cotaska側のAIスレッドを主とし、Codex SDK側の `threadId` はCotaskaスレッドに紐づく外部実行IDとして扱う。
- スレッドのタイトル、対象タスク、対象仕様変更、参照ファイル、表示順、アーカイブ状態、最終更新日時はCotaska側で保持する。
- Codex SDK側の `threadId` は、Codexへ会話文脈を継続させるためのIDとして保持する。
- Codex SDK側の `threadId` が失効、削除、再開不可になった場合でも、Cotaska側のAIスレッドと相談履歴は残す。
- Codex文脈を再開できない場合は、Cotaska側に保存された相談履歴や対象タスク、参照ファイルを元に、新しいCodexスレッドで再開できるようにする。
- 方針として「Cotaskaスレッドを主、Codexスレッドを従」とする。

## AIチャット保存方針

- AIスレッドとAIとのチャット履歴はCotaska側にも保存する。
- Cotaska側には、画面表示、監査、再開、タスク変更理由の追跡に必要な範囲を保存する。
- Codex SDK側の完全な内部文脈をCotaskaが複製することは目的としない。
- Codex SDK側の `threadId` だけに依存せず、Cotaska側の履歴から相談内容と承認履歴を追跡できるようにする。

Cotaska側に保存する主なデータ:

- AIスレッド
- ユーザー入力
- AI応答の表示本文
- 対象タスクID
- 参照ファイル
- Codex SDK側の `threadId`
- タスク更新提案
- 承認/却下/反映履歴
- 実行エラー、認証エラー、キャンセル結果

Codex側に任せる主なデータ:

- モデル内部の会話文脈
- Codex SDKが継続実行に使う詳細なセッション情報

## AI関連データ保存先方針

- AI関連データの正本はSQLiteで管理する。
- SQLiteファイルは `Cotaska/data/ai.sqlite` に配置する。
- タスク本体と仕様・設計ドキュメントの正本は、従来どおりMarkdown/YAMLで管理する。
- `data/tasks/*.md` はタスクの正本として維持する。
- `data/tasks/_index.yaml` は従来どおり生成物として扱い、手動編集しない。
- AIスレッド、チャット会話、Codex SDK側の `threadId`、参照ファイル、実行ログ、タスク更新提案、承認/却下/反映履歴はSQLiteに保存する。
- 承認後に採用されたタスク変更は、既存の `taskService` 経由で `data/tasks/*.md` に反映する。
- 採用された仕様判断や重要な技術判断は、必要に応じて仕様変更票、設計資料、`00_mgmt/DECISIONS.md` へ反映する。
- AIチャット履歴はMarkdownへ逐次保存しない。必要な場合のみ、エクスポートまたは要約としてMarkdownへ出力する。

保存先の役割分担:

| データ | 保存先 |
|---|---|
| タスク本文、frontmatter | Markdown (`data/tasks/*.md`) |
| タスク一覧インデックス | YAML生成物 (`data/tasks/_index.yaml`) |
| AIスレッド | SQLite |
| AIチャット会話 | SQLite |
| Codex SDK側の `threadId` | SQLite |
| 参照ファイル一覧 | SQLite |
| Codex実行ログ | SQLite |
| タスク更新提案 | SQLite |
| 承認/却下/反映履歴 | SQLite |
| 承認後のタスク変更 | Markdown (`data/tasks/*.md`) |
| 採用済みの仕様判断 | Markdown / `00_mgmt/DECISIONS.md` |

## 実装前確定事項

- SQLiteファイル配置:
  - `Cotaska/data/ai.sqlite`
- SQLiteライブラリ:
  - `20_app` の依存として `sql.js` を追加する。
  - ネイティブビルドを避けるため、pure JavaScript/WASMのSQLite実装を使う。
- Codex SDK導入方式:
  - `@openai/codex-sdk` を `20_app` の依存として追加する。
  - Electron main process からCodex SDKを呼び出す。
  - renderer processからはIPC経由でAI操作を依頼し、Codex SDKを直接呼ばない。
- チャット履歴保存:
  - ユーザー入力とAI応答本文は全文をSQLiteに保存する。
  - 将来、スレッド単位で削除できるようにする。
- スレッド保持方針:
  - スレッドアーカイブ機能を追加する。
  - アーカイブは論理的な非表示扱いとし、チャット履歴と提案履歴は残す。
  - 完全削除は設定画面に追加する。
  - 設定画面から「指定日数以前のAIデータを削除する」操作を提供する。
  - 削除対象日数の初期値は90日とする。
- 作業フォルダ:
  - 設定画面で作業フォルダを指定できるようにする。
  - ファイルツリーは設定された作業フォルダ配下を表示する。
  - 初期値はCotaskaリポジトリルートとする。
- Codexへ渡す参照ファイル上限:
  - 選択ファイルは最大10件を初期上限とする。
  - 合計文字数上限の初期値は100,000文字とする。
  - 上限超過時はユーザーへ表示して送信対象を調整できるようにする。
- タスク更新提案で許可する操作:
  - `update_task`
  - `create_task`
  - `update_file`
- 権限:
  - Codex SDK実行権限は設定画面で変更できる。
  - 初期値は `read-only` とし、必要に応じて `workspace-write` / `danger-full-access` を選択できる。
  - AIチャット入力欄でも送信前に一時的な権限変更を行える。
  - タスク変更やファイル変更は、原則としてCodexが直接書き込まず、提案をCotaskaが検証し、ユーザー承認後にCotaska側で反映する。

## AIデータテーブル案

AI関連テーブルの主キーは、汎用的な `id` ではなく、ドメイン上の意味が分かる `thread_id` / `message_id` / `reference_id` / `proposal_id` / `run_id` に揃える。

|---|---|---|
| thread_id | string | Cotaska側AIスレッドID |
| title | string | スレッドタイトル |
| codex_thread_id | string nullable | Codex SDK側のthreadId |
| primary_task_id | string nullable | 主対象タスクID |
| change_id | string nullable | CHG-058などの仕様変更ID |
| thread_status | string | active / archived |
| created_at | datetime | 作成日時 |
| updated_at | datetime | 更新日時 |

### ai_thread_references

### 状態区分管理方針

- 初期実装では、`thread_status` / `proposal_status` / `run_status` の状態値はコード定数で管理する。
- 各テーブルで汎用的な `status` というカラム名は使わず、状態の対象が分かるカラム名にする。
- 状態の表示名、表示順、終了状態判定、説明文などを画面や設定で扱う必要が出た場合は、将来拡張として状態マスタを追加する。

将来拡張の状態マスタ案:

### ai_status_masters

| カラム | 型 | 内容 |
|---|---|---|
| status_type | string | thread / proposal / run |
| status_code | string | active / pending / running など |
| label | string | 画面表示名 |
| sort_order | number | 表示順 |
| is_terminal | boolean | 終了状態か |
| description | text nullable | 説明 |
