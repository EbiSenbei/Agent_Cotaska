## 現象

タスクマスター配布先の `Cotaska.exe` で AI モードを利用すると、以下のエラーになる。

```text
spawn D:\Development\Git\EbiSenbei_dev\Agent_Cotaska\Cotaska\00_mgmt\Cotaska_タスク管理ツール\_app\resources\app.asar\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\codex.exe ENOENT
```

## ログ確認

初回確認時点では `00_mgmt/Cotaska_タスク管理ツール/logs/app-*.log` に上記 `codex.exe ENOENT` は記録されていなかった。

ログ出力改善後の再確認では、`00_mgmt/Cotaska_タスク管理ツール/logs/app-2026-07-09.log` に以下が記録されていた。

- `Codex CLI path resolved`
- `AI chat failed`
- `spawn ... app.asar ... codex.exe ENOENT`
- `AI chat failure context`

## 原因

`codex.exe` は Electron Builder の `asarUnpack` により、実体としては以下に存在していた。

```text
_app\resources\app.asar.unpacked\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\codex.exe
```

一方、SDK デフォルトの CLI 解決または Cotaska 側の解決結果が `app.asar` 内のパスを spawn 対象にしており、Windows では asar 内の実行ファイルを直接実行できないため `ENOENT` になった。

再発時の追加原因:

- Electron の asar 仮想 FS では `fs.existsSync(app.asar\...\codex.exe)` が true になり得る。
- 前回修正では `fs.existsSync(filePath)` を先に判定していたため、`app.asar` パスを `app.asar.unpacked` へ変換する前に「存在する」と誤判定していた。

## 修正方針

- Cotaska 側で Codex CLI の実体パスを必ず `app.asar.unpacked` 側へ解決して、SDK の `codexPathOverride` に渡す。
- `app.asar` を含むパスは、存在確認より先に必ず `app.asar.unpacked` へ変換する。
- SDK デフォルト解決へフォールバックすると `app.asar` パスへ戻るため、フォールバックせず明示的にエラー化する。
- Codex CLI の解決パスと AI 送信失敗詳細を通常ログへ出力する。

## 検証結果

- `node --check 20_app/src/main/codexSdkService.js` 成功。
- 修正後に `release-all.ps1` / `sync-task-master-release.ps1` を再実行し、タスクマスター配布先へ反映。
