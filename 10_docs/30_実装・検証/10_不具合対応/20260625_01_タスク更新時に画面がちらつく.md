## 現象

タスクを完了したり、タスク詳細を記載した後に、メインパネルのタスクリストが一瞬白くなってちらつく。
また、タスク完了後に一瞬操作できなくなる瞬間がある。

## 再現手順

1. Cotaska を起動し、メインパネルにタスクリストを表示する。
2. 任意のタスクを完了する、または詳細ペインでタスク詳細を編集・保存する。
3. メインパネルのタスクリスト表示を確認する。

## 期待動作

タスク更新後もメインパネルの表示が維持され、白画面化や短時間の操作不能が発生しない。

## 調査メモ

- 2026-06-25: T-0310 の内容をもとに起票。原因調査中。
- 2026-06-25: `App.jsx` の `loadTasks()` は毎回冒頭で `setLoading(true)` を実行する。
- 2026-06-25: メインペイン表示用の `visibleTasks` は、通常ビューで `loading === true` の間 `[]` にされるため、再読み込み中にタスクリストが一時的に空表示になる。
- 2026-06-25: タスク更新後は操作ハンドラ側で `await loadTasks()` を呼ぶうえ、ファイル保存を watcher が検知して `tasks:changed` を送信し、イベントハンドラ側でも `loadTasks()` が呼ばれる。1回の更新で再読込が二重化し、ちらつきと短時間の操作不能を起こしやすい。
- 2026-06-25: 詳細ペインの保存も `persist()` → `onSaved()` → `loadTasks()` の経路を持つため、本文編集・メタ情報編集でも同様の症状が出る可能性がある。
- 2026-06-25: `loadTasks()` に通常更新用オプションを追加し、初回ロード以外では `setLoading(true)` しないよう修正した。
- 2026-06-25: `tasks:changed` 受信時は watcher payload の `tasks` を直接反映し、renderer 側の追加 `tasks:getAll` を避けるよう修正した。

## 修正方針

- 初回ロードと通常更新ロードを分離し、通常更新時は既存の `tasks` を空にしない。
- watcher から通知される `tasks` payload を renderer 側で直接反映し、更新直後の追加 IPC と描画負荷を抑える。

## 検証結果

- 2026-06-25: 同梱 Node.js 22.14.0 の `npm.cmd run build` で Vite build 成功。
- 2026-06-25: 通常の `npm run build` は環境側 Node.js 20.18.1 と Vite 8 の要件不一致、および PowerShell の `npm.ps1` 実行ポリシーで失敗したため、同梱 Node.js 22.14.0 を使用して検証した。
