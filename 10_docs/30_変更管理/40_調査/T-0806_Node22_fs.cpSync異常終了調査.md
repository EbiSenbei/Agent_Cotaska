# T-0806 Node.js 22系のfs.cpSync異常終了調査

調査日: 2026-10-24。関連: BUG-20261024-03、T-0791、T-0792。

## 結論

大規模データに固有の問題ではない。Windows版Node.js 22.23.4で、コピー元またはコピー先のディレクトリパスに日本語があると、**空フォルダでも**フィルターなしの再帰`fs.cpSync`がプロセスごと異常終了する。英数字のみのパスなら800ファイルでも成功した。

実測・Node本体ソース・公式修正の差分から、Windowsの非ASCIIパスをネイティブコピー処理へ渡す際の文字コード変換不備が原因と判断する。22.23.4の`CpSyncCopyDir`と`CpSyncOverrideFile`には、24系で修正されたUTF-8→Windows用パス変換がない。クラッシュダンプ／ネイティブスタックは採取しておらず、0xC0000005の発生命令までは特定していない。

22.23.4を維持したまま`fs.promises.cp`で新規・上書きコピーが成功する。同期処理が必要な場合は`readdirSync`と`copyFileSync`による再帰コピーも新規コピーで成功した。`filter: () => true`の追加だけでは上書き経路に不具合が残るため、汎用修正として採用しない。

本作業は調査のみ。製品ソース、Node指定、最低セキュリティ版、配布物は変更していない。T-0806／不具合票は、実際の対応と利用者確認が済むまで未完了とする。

## 再現と境界条件

環境はWindows x64、OSビルド10.0.26200、Windows ANSI／OEMコードページ932。独立した子プロセスで実行した。合成データのコピー元ハッシュを照合し、検証先は毎回新規のworkspace配下に作成した。他のコードページでの発生範囲は未検証。

| 条件 | Node 22.23.4の結果 |
|---|---|
| 英数字パス・1ファイル／800ファイル | 成功・全ファイルSHA-256一致 |
| コピー元ディレクトリ名が日本語・1ファイル／800ファイル | 0xC0000005 |
| コピー元が日本語の空ディレクトリ | 0xC0000005 |
| コピー先ディレクトリ名が日本語 | 0xC0000005 |
| コピー元ディレクトリ名が`é` | 0xC0000409 |
| 引数のルートは英数字・内部のファイル名／子フォルダ名が日本語 | 新規ネイティブコピー成功 |
| 日本語パス・新規コピーに`filter: () => true`を追加 | 成功 |
| 日本語パス・既存ファイルをフィルター付きで上書き | ENOENT、errno 0、または0xC0000005で失敗 |
| 日本語パス・`fs.promises.cp` | 新規・上書きとも成功 |

異常終了のコードは条件によって0xC0000005または0xC0000409となる。実データの隔離スナップショットでもフィルターなしの22.23.4は0xC0000409で終了した。特定の終了コードだけで再現判定しない。

上書きの追加検証では、英数字のルート下にある日本語ファイル名も、フィルター付きのネイティブ上書き処理で異常終了した。また、コピー元が日本語のケースでは、検証用コピー先の旧ファイルを削除した後、コピーがENOENTで失敗した。フィルター追加を既存データへの安全な上書き手段と扱わない。

### 最小再現

以下を検証専用の`.cjs`として保存し、22.23.4の実体を直接指定して実行する。既存データは使わず、一時フォルダを残して証跡とする。`try/catch`ではプロセス異常終了を捕捉できないため、親プロセスで終了コードを確認する。

```js
const fs = require('node:fs');
const path = require('node:path');
const os = require('node:os');
const root = fs.mkdtempSync(path.join(os.tmpdir(), 'cotaska-cp-repro-'));
const src = path.join(root, '日本語');
fs.mkdirSync(src);
fs.cpSync(src, path.join(root, 'dest'), { recursive: true });
console.log('Copy OK'); // 22.23.4では到達しない
```

## Node側の実装と修正状況

1. 22.14.0ではディレクトリ列挙とファイルコピーをJavaScript／libuv側で実行する。22.17.0で、フィルターなしのディレクトリコピーと既存ファイル上書きをC++へ移す最適化が導入された。22.16.0／22.17.0の公開ソースでも経路の有無を確認した。ここはコードの導入境界であり、両版バイナリの実測による初発版確定ではない。
2. 22.23.4の`internal/fs/cp/cp-sync.js`は、`opts.filter`がなければ`fsBinding.cpSyncCopyDir`へ進む。`filter`があればJavaScriptで列挙するが、既存ファイルの`force`上書きは`fsBinding.cpSyncOverrideFile`へ進む。
3. 22.23.4の`src/node_file.cc`では、この2関数が`std::filesystem::path(*src)`や`*dest`を直接使用する。事前のパス検査が持つWindows向け変換とは別経路となっている。
4. 公式PR #61950はこの2関数で`src.ToPath()`／`dest.ToPath()`へ変換してから処理する修正。Node 24.15.0の公式変更履歴に収録され、24.22.0のソースにも修正を確認した。22.23.4には入っていない。
5. 2026-10-24取得の公式`dist/index.json`では22系最新は22.23.4。22系で利用できる後続修正版は確認できなかった。PR #62519は**closed・未マージ**であり、公式に採用された修正として扱わない。

24.15.0は修正導入版の説明に使用する。今回のセキュリティ基準を満たす移行候補としては、2026-10-21のセキュリティリリース24.22.1を別途検証した。現在のCotaskaは`>=22.23.4 <23`を要求するため、24系への開発環境移行にはengines・起動／CI／ビルド等の変更と総合検証が必要。

## バージョン比較と実データ検証

| 実体 | 検証結果 |
|---|---|
| Node 22.14.0 | 合成条件28ケース成功。比較用のみで運用へ戻していない |
| Node 22.23.4 | 基本28ケース中、フィルターなしの日本語ルート2ケースが異常終了。他26ケース成功。追加24ケースでは上記の空フォルダ・上書き等も確認 |
| 公式Node 24.22.1 | 空フォルダ・日本語・アクセント・上書きを含む追加24ケースすべて成功 |
| Electron 44.9.3／内蔵Node 24.22.0 | `ELECTRON_RUN_AS_NODE=1`による追加24ケースすべて成功 |

公式Node 24.22.1は検証用workspaceにのみ配置し、HTTPSの公式`SHASUMS256.txt`とWindows x64 `node.exe`のSHA-256を照合した。SHA-256: `d702daa815eabbff763c7d3808e235cf031cf2ca70211b56847bc72f51e240e5`。PATH・標準Nodeは変更していない。

稼働中Cotaskaのtasks **782ファイル**をPythonで日本語パスの隔離スナップショットへ複製し、作成時に元データとの全ファイルSHA-256一致を確認した。この同一スナップショットに対し、22.23.4のフィルター付き／非同期／手動再帰、24.22.1の通常`cpSync`、Electronの通常`cpSync`の5経路は全782ファイルが一致。22.23.4の通常`cpSync`はコピー0ファイルで異常終了した。検証後のスナップショットも不変。

最初のライブtasks直接比較では、実行中に別作業のT-0801と生成インデックスが更新され、処理後半の比較基準が変わった。その試行は全件一致の根拠にせず、上記の不変スナップショットで再実行した。DB・設定・利用者のタスク本文を書き換える検証はしていない。T-0806自体の管理情報のみ本調査の記録として更新する。

## Cotaskaへの影響と推奨対応

| 箇所 | 現状の経路／影響 |
|---|---|
| `20_app/scripts/prepare-pdf-assets.js` | 開発・ビルド前のフィルターなし再帰コピー。日本語の作業フォルダでは本件の対象となる可能性が高い |
| `20_app/src/main/settingsService.js`の`copyLegacyEntryIfMissing` | 旧データ移行のフィルターなしコピー。22.23.4で直接動かす場合は対象 |
| `20_app/src/main/taskFileBundle.js`の`copyVerified` | アーカイブ等の資料コピー。22.23.4で直接動かす場合は対象 |
| `20_app/src/main/backupService.js` | 再帰コピーに既存フィルターあり。復元はコピー前にコピー先内容を除くため、今回の新規フィルター経路に相当。ただしフィルター有りだけで一般の上書き安全性を保証しない |
| 配布Electron 44.9.3 | 本件のコピー再現なし。開発用Node22の問題を、そのまま配布アプリの再現済み不具合とは扱わない |

最低セキュリティ版と22系維持を両立する第一候補は、問題のあるディレクトリコピーを`fs.promises.cp`へ変更し、呼出元で完了を待つ対応。同期APIを維持する必要がある箇所は、通常ファイル／ディレクトリを明示的に扱う同期再帰コピーを候補とする。今回の手動コピー検証は新規コピーのみであり、リンク・上書き・属性・タイムスタンプ・失敗時の中途状態の仕様を満たす製品実装は別途必要。

24.22.1への移行も修正候補だが、コピーだけ成功した結果を開発環境全体の互換性確認とは扱わない。旧版への切戻し、非ASCIIの利用禁止、全体的な`fs.cpSync`のモンキーパッチは採用しない。

残作業は、22系での回避実装方針の確定、対象箇所への適用、日本語パスの新規・再実行・上書き・衝突・失敗時の回帰検証、既存バックアップ／復元テスト、必要な利用者確認。今回、製品のバックアップ／復元を新たに実行したとは扱わない。
