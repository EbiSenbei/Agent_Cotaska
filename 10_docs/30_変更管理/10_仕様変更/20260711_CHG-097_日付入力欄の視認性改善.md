# CHG-097 日付入力欄の視認性改善

## 基本情報

| 項目 | 内容 |
| --- | --- |
| 変更ID | CHG-097 |
| 起票日 | 2026-07-11 |
| 起票元 | T-0412 |
| ステータス | ユーザー確認待ち |
| 優先度 | normal |

## 変更内容

Cotaska の日付入力欄を、日付の値を読み取りやすく、直接入力できる欄であることが分かるテキストボックス風の UI に改善する。

カレンダーからの日付選択、日付のクリア、既存のショートカット操作および時刻指定がある画面ではその操作性を維持する。

## 変更理由

現行の日付入力欄は入力欄として認識しにくく、日付をどこで確認・編集するのかが分かりにくいという指摘があったため。

## 対象範囲

- タスクの期限日・締切日など、Cotaska 内で共通利用している日付入力 UI
- 日付選択コンポーネントと、その利用画面の表示・編集操作

設計時に全ての利用箇所を確認し、対象と非対象を明確化する。

## 非対象

- タスクデータの保存形式（`due_date`、`deadline_date`）の変更
- 日付の計算・通知仕様の変更
- 既存データの移行

## 影響範囲

| 区分 | 影響 |
| --- | --- |
| UI | 日付入力コンポーネント、および期限日・締切日を編集する画面 |
| データ | なし。既存の保存形式を維持する |
| IPC/API | 原則なし |
| 既存操作 | カレンダー選択、直接入力、クリア、ショートカット、時刻指定の回帰確認が必要 |

## 完了条件

1. 日付値がテキストボックス風の入力欄として明確に見えること。
2. キーボードによる日付入力と、カレンダーによる選択ができること。
3. 期限日・締切日の保存、再表示、クリアが従来どおり動作すること。
4. 対象となる全画面で見た目と操作が一貫していること。
5. ユーザー確認タスクを完了すること。

## 設計結果

- 対象は詳細ペインのメタ情報にある「日付」（`due_date`）と「期限」（`deadline_date`）とする。
- 現在の文字列クリック領域を、日付値または「未設定」とカレンダーアイコンを内包するテキストボックス風フィールドへ置き換える。
- 詳細ペインでは日付のみの値を `MM/DD` で表示し、「進捗」「日付」「期限」「優先度」を一行に収める。
- フィールド全体のクリックとキーボードフォーカスで、既存の `DueDatePopover` を開く。
- 日付の直接入力、カレンダー選択、クリア、時刻選択、日付ショートカットは `DueDatePopover` 内の既存仕様を維持する。
- `due_date` と `deadline_date` の保存形式、IPC、既存データの移行は不要とする。

## 実装結果

- 詳細ペインの「日付」「期限」を、カレンダーアイコン付きのテキストボックス風フィールドへ変更した。
- 日付表示を `MM/DD` に短縮し、進捗・日付・期限・優先度を一行に収めた。
- 既存の `DueDatePopover` を継続利用し、データ形式、IPC、日付選択・直接入力・クリア・ショートカット・時刻指定の仕様を維持した。
- Vite 本番ビルドに成功した。
