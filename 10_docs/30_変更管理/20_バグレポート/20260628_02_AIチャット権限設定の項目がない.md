## 現象

CHG-058の仕様ではCodex SDK実行権限の方針が記載されているが、設定画面に権限を変更する項目がない。

## 期待動作

設定画面でAIチャットの既定権限を変更できる。
初期値は読み取り専用とし、必要に応じて作業フォルダ書き込み可、フルアクセスを選択できる。

## 調査メモ

- AIチャット入力欄には一時的な権限選択を追加済みだった。
- ただし `settings.yaml` に既定権限を保存する項目と、設定画面の編集項目が未実装だった。
- Codex SDK TypeScript SDKは `sandboxMode` として `read-only` / `workspace-write` / `danger-full-access` を受け取れる。

## 修正方針

- `settings.yaml` の `aiChat.sandboxMode` として既定権限を保存する。
- 設定画面に「権限」セレクタを追加する。
- AIチャット画面は設定値を初期値として読み込む。
- Codex SDK送信時に権限指定が省略された場合も設定値を使う。
- CHG-058仕様変更票と基本設計を新方針へ更新する。

## 検証結果

- `vite build` が成功することを確認。

## 追加調査（2026-06-28）

ユーザー動作確認で、チャット欄の権限を「フルアクセス」にしても Codex からファイル更新できず `Access denied` になる事象を確認。

- 実行履歴DBの `ai_runs.sandbox` に旧表記の `read_only` が残っており、実行時の権限とUI表示の対応を追いにくい状態だった。
- `data/settings.yaml` に `aiChat.sandboxMode` が未保存の状態では、AIチャット画面初期表示は既定値 `read-only` になる。
- 設定画面で権限を保存しても、AIチャット画面が既に開いている場合はセレクタ表示へ即時反映されない可能性があった。
- チャット欄の権限セレクタは画面状態としてのみ保持され、設定ファイルへ保存されていなかった。

## 追加修正（2026-06-28）

- `ai_runs.sandbox` の既定値を `read-only` 表記へ統一した。
- チャット欄の権限セレクタ変更時に `settings.yaml` の `aiChat.sandboxMode` へ保存するようにした。
- 設定画面保存時にAIチャット設定変更イベントを発火し、AIチャット画面の権限セレクタへ即時同期するようにした。
- 送信時はセレクタの値を正規化してから Codex SDK へ渡すようにした。

## 追加検証（2026-06-28）

- 同梱Node.jsをPATH先頭にして `npm run build` が成功することを確認。

## 追加調査2（2026-06-28）

ユーザー動作確認で、設定画面の「権限」を「読み取り専用」から「作業フォルダ」に変更して保存しても反映されず、Codex実行履歴も `read_only` のままになる事象を確認。

- `settingsService.getDataDir()` が `process.cwd()` 依存で `../data` を参照していた。
- 起動ディレクトリや検証コマンドの実行位置によって、`Cotaska/data/settings.yaml` ではない別の `data/settings.yaml` を読みに行く可能性があった。
- その結果、設定画面で保存した権限と、Codex SDK送信時に参照する権限がズレ、`read-only` のまま実行され得る状態だった。

## 追加修正2（2026-06-28）

- `settingsService` のデータディレクトリを `Cotaska/data` に固定した。
- `DEFAULT_SETTINGS.aiChat.workdir` も `Cotaska` リポジトリルートに固定した。
- 本来の `Cotaska/data/settings.yaml` に `sandboxMode: "workspace-write"` を反映した。
- 調査中に誤って作成された `Agent_Cotaska/data/settings.yaml` は、対象ディレクトリがその1ファイルのみであることを確認して削除した。

## 追加検証2（2026-06-28）

- `Cotaska` 直下と `Cotaska/20_app` 直下のどちらから `settingsService.getSettings()` を呼んでも、同じ `Cotaska/data/settings.yaml` と `sandboxMode: workspace-write` を返すことを確認。
- 同梱Node.jsをPATH先頭にして `npm run build` が成功することを確認。
