## 現象

`upload-github-release.ps1`で未作成のタグを公開しようとすると、Release不存在を正常系として判定する前にPowerShellの`$ErrorActionPreference = "Stop"`が`gh release view`のstderrを例外化し、公開処理が停止する。

## 再現手順

1. GitHubに存在しないバージョンのNSIS成果物とリリースノートを用意する。
2. `upload-github-release.ps1 -Version <version>`を実行する。
3. `gh release view`の`release not found`でスクリプトが停止する。

## 期待動作

`release not found`を「同名Releaseなし」という公開可能な状態として扱い、そのほかの取得失敗と既存Releaseだけを停止条件にする。

## 調査メモ

- `gh release view`はRelease不存在時に終了コード1とstderr `release not found`を返す。
- スクリプトは終了コードと文言を判定する実装だが、グローバルの`$ErrorActionPreference = "Stop"`により判定箇所まで到達できなかった。
- 最初の公開試行はRelease作成前に停止しており、GitHub側の変更は発生していない。

## 修正方針

Release存在確認の呼出し中だけ`ErrorActionPreference`を`Continue`へ切り替え、終了コードとstderrを取得後に元の値へ必ず戻す。

## 検証結果

- 修正後のスクリプトで未作成の`v0.4.4`を公開可能と判定した。
- GitHub Releaseの作成とNSIS成果物3点のアップロードに成功した。
- 公開後検証で各成果物のファイル名、サイズ、`uploaded`状態が一致した。
- 公開URL: https://github.com/EbiSenbei/cotaska-site/releases/tag/v0.4.4
- ユーザー確認後に解決済みへ更新する。
