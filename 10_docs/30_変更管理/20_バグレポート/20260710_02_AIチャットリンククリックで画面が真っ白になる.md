## 現象

AIチャット上の Markdown リンクをクリックすると、Cotaska のメイン画面が真っ白になる。

確認ログ:

- `00_mgmt/Cotaska_タスク管理ツール/logs/app-2026-07-09.log`

該当ログ:

- `2026-07-10T00:12:10.124Z` に `Renderer load failed: code=-6, desc=ERR_FILE_NOT_FOUND` が出力されていた。
- 遷移先は `file:///D:/Development/Git/EbiSenbei_dev/Agent_Cotaska/Cotaska/10_docs/30_実装・検証/10_不具合対応/20260710_01_アプリ更新時のバックアップパスが長すぎる.md:1`。

## 再現手順

1. 対策前の Cotaska 0.2.8 を起動する。
2. AIチャットの応答内に表示されたローカル Markdown ファイルへのリンクをクリックする。
3. アプリのメインウィンドウが `file://...md:行番号` へ直接遷移し、読み込み失敗により白画面になる。

## 期待動作

AIチャット上のリンクをクリックしても、Cotaska のメインウィンドウはアプリ画面に留まる。
ローカルファイルや URL は、外部アプリまたは既定ブラウザで開く。

## 調査メモ

- ログには `Renderer load failed` と Electron の `Failed to load URL` 警告が記録されていた。
- 実行中のアプリはログ上 `version: 0.2.8` だった。
- 配置済み `00_mgmt/Cotaska_タスク管理ツール/_app/resources/app.asar` を展開確認したところ、以下の対策が未含有だった。
  - `will-navigate` によるアプリ外遷移ブロック
  - `setWindowOpenHandler` による外部リンクの別処理
  - AIチャット Markdown リンクの `handleOpenMarkdownLink` 処理
  - `:1` などの行番号サフィックスを除去する `stripFileLineSuffixIfExists`
- 現行ソースには上記対策が存在する。
- 0.2.9 への Portable 更新は `portable-update-20260710_084536.log` 上、更新前バックアップパス長の問題で失敗していたため、対策済みビルドが実行環境へ反映されていなかった。

## 修正方針

- 現行ソースに含まれる AIチャットリンク処理とメインウィンドウ遷移ガードを維持する。
- BUG-20260710-01 の Portable 更新失敗を解消し、0.2.9 の対策済みビルドが実行環境へ反映されるようにする。
- 反映後、AIチャット上のローカル Markdown リンククリックで白画面にならず、既定アプリで開くことを確認する。

## 検証結果

- 配置済み 0.2.8 の `app.asar` に対策コードが含まれていないことを確認した。
- 現行ソースの `20_app/src/main/main.js` と `20_app/src/renderer/components/AiChatPane.jsx` には対策コードが含まれていることを確認した。
- 実機での再確認は、BUG-20260710-01 の更新反映後にユーザー確認待ち。
