# AIチャット内ローカルリンクで画面が真っ白になる

## 基本情報

| 項目 | 内容 |
|------|------|
| 番号 | BUG-20260709-04 |
| 報告日 | 2026-07-09 |
| 報告者 | ユーザー |
| 対象機能 | AIモード / AIチャット |
| 重要度 | 高 |
| 状態 | 対応中 |

## 現象

`Cotaska.exe` で起動したリリース版Cotaskaが、AIチャットでCodexからの返事待ち中に真っ白画面になった。

## 再現手順

1. `00_mgmt/Cotaska_タスク管理ツール/Cotaska.exe` からCotaskaを起動する。
2. AIモードでCodexへ送信する。
3. Codex応答中または応答表示後、AIチャット内のローカルファイルリンクを開く。

## 調査メモ

- `logs/app-2026-07-09.log` に以下のログを確認した。
  - `Renderer load failed: code=-6, desc=ERR_FILE_NOT_FOUND, url=file:///D:/Development/Git/EbiSenbei_dev/Agent_Cotaska/Cotaska/00_mgmt/DECISIONS.md:465`
  - その直後に `Renderer did-finish-load` のURLも `DECISIONS.md:465` になっていた。
- 本来の画面URLは `.../_app/resources/app.asar/dist/renderer/index.html`。
- AIチャット本文のMarkdown表示では、タスクIDリンクだけ `preventDefault()` していたが、通常の `<a href="file:///...">` は既定動作のままだった。
- そのためElectronのメインウィンドウ自体がローカルファイルURLへ遷移し、存在しない `DECISIONS.md:465` を読み込もうとして白画面になったと判断する。

## 修正方針

- AIチャット内の通常リンククリックをrenderer側で捕捉し、Electronウィンドウを遷移させず `shell.openTarget` へ渡す。
- main process側でも `will-navigate` / `setWindowOpenHandler` でアプリ本体以外への遷移をブロックする。
- `file:///.../file.md:465` のような行番号付きローカルファイルURLは、存在確認時に実ファイルパスへ補正する。

## 対応内容

- `20_app/src/renderer/components/AiChatPane.jsx`
  - `MarkdownPreview` に通常リンクのクリック捕捉を追加。
  - `handleOpenMarkdownLink()` を追加し、リンクを `window.cotaskaAPI.shell.openTarget()` で外部起動するように変更。
- `20_app/src/main/main.js`
  - `stripFileLineSuffixIfExists()` を追加。
  - `openShellTarget()` で行番号付きfile URLを実ファイルパスへ補正。
  - `BrowserWindow.webContents` の `will-navigate` と `setWindowOpenHandler` でアプリ外URLへの遷移をブロック。

## 検証

- `node --check 20_app/src/main/main.js`: 成功。
- 通常PATHの `npm run build`: Node.js 20.18.1 / Vite要件不足で失敗。
- Codex同梱 Node.js v24.14.0 をPATH先頭にして `npm run build`: 成功。

## 残課題

- 現在起動中の配布フォルダ版には未反映。リリース/配布フォルダへ反映するにはビルド済み成果物の同期または再パッケージが必要。
- 実機でAIチャット内の `file:///.../DECISIONS.md:465` リンクをクリックして、画面が遷移せず外部アプリ起動またはエラー表示になることを確認する。
