## 現象

Portable 更新は完了して Cotaska が再起動するが、更新中に `CotaskaUpdater.exe` の状態ダイアログが表示されない。

2026-08-22 の再確認では表示されるようになった一方、更新完了後もダイアログが自動で閉じない。

## 再現手順

1. Portable 版 Cotaska で更新ファイルをダウンロードする。
2. 「再起動して更新」を実行する。
3. Cotaska 終了から再起動までの間を確認する。

## 期待動作

更新開始から再起動要求まで、`Cotaska を更新しています` ダイアログが前面に表示され、現在の処理段階を示す。

## 調査メモ

- 2026-07-25 の `logs/portable-update-20260725_222446.log` で、`CotaskaUpdater.exe` による更新処理の完了を確認した。
- アプリログでも `tools/CotaskaUpdater.exe` を一時作業フォルダへコピーして起動しており、PowerShell フォールバックは使用していない。
- 既存実装は Windows Forms の状態ウィンドウをバックグラウンド UI スレッドで生成し、表示に失敗しても 3 秒後に更新処理を継続していた。そのため、表示失敗を検知・記録できなかった。
- 2026-08-22 の `portable-update-20260822_150447.log` は `Portable update completed` と `Cotaska restart requested` を記録しており、更新と再起動は成功していた。
- `UpdaterStatusWindow.OnFormClosing()` は `CloseReason.UserClosing` を常にキャンセルしていたため、updater が `window.Close()` を呼ぶ自動クローズも拒否していた。

## 修正方針

- Windows Forms のメイン UI スレッドで状態ウィンドウを開始し、更新処理のみをワーカースレッドで実行する。
- updater 起動時の `windowsHide` を無効化し、状態ウィンドウを非表示にしない。
- 隔離した Portable 環境で待機状態を作り、状態ウィンドウのタイトルと応答状態を確認する。
- 内部の自動クローズ時だけ閉じることを許可し、利用者による閉じる操作は従来どおり拒否する。

## 検証結果

- `20_app/setup/updater/build.ps1` により `CotaskaUpdater.exe` を再ビルドした。
- 隔離環境で updater を Cotaska 終了待ちにしたところ、`Cotaska を更新しています` のウィンドウが生成され、応答状態であることを確認した。
- 実利用環境での更新確認は T-0460 と T-0523 でユーザー確認待ちとする。
- 自動クローズの回帰修正後、隔離環境で正常更新を完了させた。Cotaska 終了待ち中に状態ダイアログが応答可能な状態で表示され、更新後は updater プロセスが終了コード 0 で終了することを確認した。
