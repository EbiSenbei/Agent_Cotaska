## 現象

`upload-r2.ps1`の開始時に`Get-CotaskaGitCommit`を呼び出すと、`if`がコマンドとして解釈され、GitコミットIDを取得できずR2公開処理が停止する。

## 再現手順

1. Windows PowerShell 5.1で`20_app/upload-r2.ps1`を実行する。
2. `Get-CotaskaGitCommit`が`git rev-parse HEAD`を実行する。
3. `The term 'if' is not recognized`エラーで処理が終了する。

## 期待動作

現在のGitコミットIDを取得し、検証済みのZIP、SHA-256、version.jsonをCloudflare R2へ公開できる。

## 調査メモ

- `release-common.ps1`の`return if (...) { ... } else { ... }`は構文解析を通過するが、Windows PowerShell 5.1の実行時には`if`をreturn値の式として評価せず、コマンド呼び出しとして扱う。
- エラーはR2用Node.js処理の開始前に発生しており、今回の失敗試行では外部ファイルをアップロードしていない。

## 修正方針

- Gitコマンド成功時の`return`と、失敗時の`return "unknown"`を明示的な分岐へ変更する。
- Windows PowerShell 5.1で構文解析、成功経路、失敗時フォールバックを検証する。
- 修正を含むv0.3.5配布物を再生成し、共通成果物検証後にR2公開を再実行する。

## 関連ファイル

- `20_app/scripts/release-common.ps1` — リリース処理の共通関数正本
- `00_mgmt/Cotaska_タスク管理ツール/tools/release-common.ps1` — タスク管理ツール配布先の同期コピー
- `20_app/upload-r2.ps1` — R2公開処理の呼び出し元

## 検証結果

- Windows PowerShell 5.1で両方の`release-common.ps1`を構文解析し、エラー0件を確認した。
- 正常なGitリポジトリでは40桁のコミットID、Git情報を取得できないパスでは`unknown`を返すことを確認した。
- 修正コミット`f5770c0`からv0.3.5を再生成し、全出荷チェックと共通成果物検証に成功した。
- R2公開を再実行し、ZIP、SHA-256、version.jsonのアップロードと公開HTTP 200確認に成功した。
- 公開version.jsonのversionは`0.3.5`、gitCommitは`f5770c025992ce1451b8e5fa483a7ee00abfc13f`である。
- 公開SHA-256とローカルZIPのSHA-256は`acbc234ad441f6a70178992cf43d0a4b3524a7774aa15930c03e47d86ca4b9fb`で一致した。
- Cotaskaからの更新確認・ダウンロードはユーザー確認待ちとする。
