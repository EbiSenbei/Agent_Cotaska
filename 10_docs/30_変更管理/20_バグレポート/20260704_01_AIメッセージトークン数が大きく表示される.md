## 現象

AIチャットのassistantメッセージ保存時に、`ai_messages.token_count` が実態より大きく保存される。

## 再現手順

1. AIチャットでCodex SDKへメッセージを送信する。
2. 応答完了後、`ai_messages.token_count` を確認する。
3. Codex SDKの `usage` に含まれる `cached_input_tokens` も合計へ加算され、値が大きくなる。

## 期待動作

`cached_input_tokens` は `input_tokens` の内訳として扱い、`token_count` の合計へ二重加算しない。

## 調査メモ

`20_app/src/main/codexSdkService.js` の `summarizeUsage()` で、`input_tokens + cached_input_tokens + output_tokens + reasoning_output_tokens` を合計していた。

Codex SDKのusageでは `cached_input_tokens` は入力トークンのキャッシュ内訳として扱うべき値のため、合計値へ別加算すると二重計上になる。

## 修正方針

`summarizeUsage()` を `input_tokens + output_tokens + reasoning_output_tokens` の合計へ変更する。

既存DBの過去値は調査ログとして残っている値のため、今回の修正では自動補正しない。必要になった場合は別途データ補正タスクとして扱う。

## 検証結果

- bundled Node v22.14.0 で `npm.cmd run build` 成功。
- 新規AI応答の実データを確認し、`ai_messages.token_count` が `input_tokens + output_tokens + reasoning_output_tokens` と一致することを確認。
- ユーザー確認により解決済み。
