## 現象

子タスクの進捗ステータスを保留に変更すると、親タスクの進捗ステータスも連動して保留になってしまう。

子タスクの保留は、その子タスクだけの状態として扱われるべきであり、親タスクへ自動反映されないでほしい。

## 再現手順

1. 親タスクと、その配下に子タスクがある状態を用意する。
2. 子タスクの進捗ステータスを保留に変更する。
3. 親タスクの進捗ステータスを確認する。

## 期待動作

子タスクを保留にしても、親タスクの進捗ステータスは変更されない。

親タスクを保留にしたい場合は、親タスク自身を明示的に保留へ変更したときだけ反映される。

## 調査メモ

- `20_app/src/main/taskService.js` の `estimateParentState()` で、未着の親タスクに対して子タスクの `保留` を親の `保留` として推定していた。
- 起動時の renderer 側補正でも `20_app/src/renderer/lib/taskViewModel.js` の `calcParentProgress()` が同じ判定を持っていたため、表示初期化時にも親へ保留が伝播する可能性があった。
- 親タスクを明示的に保留にした場合、子孫を保留へ同期する既存処理は別経路のため維持する。

## 修正方針

- 子タスクから親タスクを再推定する処理では、`仕掛` / `完了` の子タスクがある場合だけ親を `仕掛` へ自動開始する。
- 子タスクの `保留` は親タスクへ伝播させない。

## 修正結果

- `20_app/src/main/taskService.js` の `estimateParentState()` から、子タスクの `保留` を親タスクの `保留` として返す分岐を削除した。
- `20_app/src/renderer/lib/taskViewModel.js` の `calcParentProgress()` からも同じ分岐を削除し、起動時補正と保存時補正の挙動を揃えた。
- 同梱 Node.js 22.14.0 で `npm run build` 成功。
- 状態を `解決済み` とした。
