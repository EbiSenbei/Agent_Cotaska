# Cotaska タスクフォルダ移行

同梱の [移行スクリプト](scripts/migrate-task-folders.cjs) を使用する。対象は `tasks` の親フォルダを明示し、PC固有のパスを推測して実行しない。`data/tasks` と `tasks` の両配置に対応する。

## 前提

- Node.jsと、このリポジトリの `20_app` の依存関係（js-yaml）が必要。未導入なら `20_app` で `npm ci` を実施する。
- 対象PCでタスクフォルダ形式、添付フォルダの探索除外、新規作成、アーカイブ、バックアップ・復元に対応したCotaskaを用意する。本スキルの追加だけではアプリは対応しない。
- ユーザーが指定したプロジェクトだけを扱う。スキル作成・調査の依頼を実データ移行の許可と解釈しない。移行を依頼済みなら同じ許可を繰り返し求めない。
- Cotaskaを終了する。`--app-stopped` と `--compatible-app` は実際の確認後に付ける自己申告フラグであり、スクリプトは起動状態や版の互換性を自動判定しない。
- 同期データは全PCのアプリと同期を停止して一か所で移行する。独立したデータはプロジェクトごとに実施する。同期再開は全PCの対応版への更新後に行う。

## 手順

1. リポジトリと対象プロジェクトのAGENTS.md、タスク運用ルール、`tasks/_index.yaml`、対象タスクを読む。対象パス、対応版、同期の有無を確認する。
2. 以下を事前実行する（書き込みなし）。出力の対象ルート、各IDと移動予定、件数を確認する。重複ID、ID不一致、不正YAML、移動先衝突、リンク、タスク以外のMarkdownは停止条件。添付内Markdownは探索しない。

   本文の既存相対リンクは移動により基準フォルダが変わる。スクリプトは本文を変更しないため、移行前に相対リンクを調べ、コピー環境でリンク先を確認する。必要なリンク修正は別途内容を記録して行い、本文のハッシュ一致検証と混同しない。

   ```powershell
   node <skill-dir>/scripts/migrate-task-folders.cjs --root <tasksの親フォルダ>
   ```

3. まず対象データのコピーで適用し、対応版Cotaskaで表示・編集・添付・アーカイブ・バックアップ復元を検証する。アプリ対応が未実装なら事前確認までとし、本番適用を行わない。
4. 本番適用には対象外にあるバックアップ先を明示する。

   ```powershell
   node <skill-dir>/scripts/migrate-task-folders.cjs --root <tasksの親フォルダ> --apply --backup-dir <対象外のバックアップ先> --app-stopped --compatible-app
   ```

   スクリプトは対象フォルダ全体を `cotaska-migration-*/snapshot` にコピーし、全ファイルのSHA-256を照合してから本文を移動する。manifest.jsonとjournal.jsonlが元のパス・ハッシュ・移動結果を記録する。バックアップ先には十分な空き容量を確保する。

5. 適用後に事前実行を繰り返し、pendingが0、IDと件数が一致することを確認する。スクリプトは全ファイルの移動後パスと内容も照合する。本文・frontmatter・添付・設定・アーカイブは書き換えない。旧配置のサブフォルダは保ち、その直下にIDフォルダを作る。空の添付フォルダは作らない。
6. 対応版Cotaskaでインデックスを再生成し、一覧と編集を確認する。スクリプトは `_index.yaml` を変更しない。再生成が成功するまでは移行完了と報告しない。旧バックアップからの復元もコピー環境で確認する。
7. PC・プロジェクトごとに対象パス、版、件数、バックアップ・ログの場所、検証結果を記録する。ユーザーの画面確認まではバックアップを保持する。

## 中断・復旧

移動済みタスクは再実行時にスキップする。途中で失敗した場合はログと実ファイルを照合してから再実行する。mkdir後・移動前の中断では空のIDフォルダが残り、衝突として停止する。その場合は内容が空であることとログのbegin記録を確認し、その空フォルダだけを取り除く。非空フォルダや元本文を消して解決しない。

戻す場合はアプリと同期を停止し、現在のデータも別場所に保全する。snapshotを新しい復旧用フォルダへコピーし、manifestのoriginalハッシュと全ファイルを照合してから旧版で使用する。既存データへの直接上書きや自動削除はしない。移行後に編集した内容はsnapshotに含まれないので、別途保持して差分を確認する。

本ツールは既存アーカイブの再配置、添付ZIP化、添付UI、バックアップ互換性の実装を行わない。T-0579全体の完了とは区別して報告する。
