# Claude Code 連携の検討（個人利用前提）

> 作成日: 2026-07-13
> 関連: CHG-102（Claude Code チャット連携）、CHG-058（Codex SDK チャット連携）、T-0159（Claude連携を見据えたAIプロバイダ拡張）

## 1. 概要

Cotaska の AI チャット機能について、現在の Codex 連携に加えて **Claude Code を選択肢として利用可能にする**ことを検討する。
設定画面で連携先を「Codex / Claude Code」から選択し、選択に応じてチャットが動作する仕様を目指す。

**大前提（重要）**: 本連携は **個人利用（自分のみが使用し、配布しない）** を目的とする。
規約上、Claude のサブスクリプション認証を第三者配布アプリで使うことは禁止されているため、**配布版には含めない**方針とする。

---

## 2. 検討の経緯と結論

### 2.1 当初やりたかったこと

- Codex 同様、**API キーを使わないログイン認証**（サブスクリプションログイン）で Claude Code を利用したい。
- ターゲット層（一般開発者）は BYO API キーをほとんど使わないため、API キー入力方式は現実的でない。

### 2.2 認証・規約（ToS）調査の結論

詳細は `workspace/temp/20260713_01_ClaudeCode連携の検討/認証方式とToS調査結果.md` を参照。要点は以下。

| 認証方式 × 配布形態 | Codex（OpenAI） | Claude（Anthropic） |
|---|---|---|
| サブスクログイン + 第三者**配布**アプリ | 🟡 グレー（明文の禁止なし） | 🔴 **不可**（明文で禁止・要事前承認） |
| BYO API キー | 🟢 公式サポート | 🟢 公式サポート |
| 開発者**本人のみ**が利用（配布しない） | 🟡 グレー（個人利用寄り） | 🟡 **グレー（個人利用寄り・現実的にあり）** |

- Anthropic は「第三者開発者がサブスク資格情報を経由してリクエストを送ること」を**名指しで禁止**している。
- 禁止条項の主語は「第三者開発者」で、**有償/無償は無関係**。効く境界は「**本人のみ利用 か／他者へ配布 か**」。
- VSCode / JetBrains 拡張がサブスクで動くのは **Anthropic 純正（ファーストパーティ）製品だから**であり、Cotaska の根拠にはならない。
- `@anthropic-ai/claude-agent-sdk` は内部で `claude` CLI を起動しているだけなので、**「SDK ではなく CLI を直接起動」しても規約上の判断は変わらない**（技術的手段の違いは無関係）。

### 2.3 今回の判断

- **配布**を伴う限り Claude のサブスク認証利用は不可。
- ただし **個人利用（配布しない）** であれば、禁止条項の「第三者に product を提供」の構図から外れ、**グレーだが現実的にあり得る**領域となる。
- よって本件は **「個人利用限定で Claude Code 連携を実装し、配布版には含めない」** という前提で進める。
- あわせて、規約リスクをゼロにできる **クラウドプロバイダ（Amazon Bedrock）経由**の認証モードも選択肢として設計に含める（後述 2.4）。

### 2.4 Claude 認証モードの2系統

Claude 側は認証モードを2つ持てる設計とする。設定画面で選択する。

| Claude 認証モード | 認証手段 | 課金 | 規約 | 配布 | 位置づけ |
|---|---|---|---|---|---|
| **ローカルサブスク認証** | ローカルの Claude Code ログイン（`~/.claude/`） | サブスク定額 | 🟡 個人利用のみグレー | ❌ 不可 | 手軽。個人利用限定 |
| **クラウドプロバイダ（Bedrock）** | AWS 資格情報 + `CLAUDE_CODE_USE_BEDROCK=1` | 従量課金（AWS 請求） | 🟢 クリーン（第三者アプリ公式パス） | ✅ 可 | 規約クリーンだがセットアップが重い |

- **Bedrock は当初要件「API キー不要のログイン認証」は満たさない**（実質 API キー相当。AWS アカウント + Bedrock 有効化 + Claude モデル利用申請 + 資格情報発行が必要）。
- ただし Anthropic が第三者アプリに公式サポートする認証パス（Bedrock / Vertex / Foundry）の一つであり、**配布アプリでも規約上クリーン**。
- トレードオフ: 「規約リスクをゼロにしたいなら Bedrock、ログイン認証の手軽さを取るなら個人利用限定のローカル認証」。
- 実装は Claude プロバイダ内でこの2モードを切替可能にする（`claudeAuthMode: "local" | "bedrock"` など）。

## 3. 現状の実装構造（Codex）

```
[renderer] AiChatPane.jsx / SettingsPane.jsx
    │  window.cotaskaAPI.aiChat.*
    ▼
[main] main.js  ipcMain.handle("aiChat:*")
    │  ── sendMessage / checkAuthStatus / cancelRun / listActiveRuns / listRunEvents
    │       → codexSdkService  にハードコードで委譲
    │  ── listThreads / addMessage / … （DB系）
    │       → aiService（sql.js: ai.sqlite）
    ▼
codexSdkService.js
    - @openai/codex-sdk + 同梱 codex CLI バイナリ
    - codexThread.runStreamed(prompt) でストリーミング
    - codex doctor --json で認証判定
```

- **プロバイダ依存なのは IPC の 5 メソッドのみ**（`sendMessage` / `checkAuthStatus` / `cancelRun` / `listActiveRuns` / `listRunEvents`）。
- スレッド/メッセージ/参照/提案などの DB 系（`aiService`）、UI、参照ファイルの仕組みはプロバイダ非依存で共用できる。

## 4. 目標アーキテクチャ（Codex / Claude 切替）

```
[main] main.js  ipcMain.handle("aiChat:*")
    │  provider = settings.aiChat.provider  ("codex" | "claude")
    ▼
aiProviderRegistry.js  （新設：ディスパッチャ）
    ├─ "codex"  → codexSdkService     （既存）
    └─ "claude" → claudeCodeService    （新設）
                  ↑ codexSdkService と同一シグネチャ
[main] aiService（DB系：両プロバイダ共用、変更なし）
```

`codexSdkService` と `claudeCodeService` は**同一シグネチャ**を実装する共通インターフェースとする。
main.js の各 `aiChat:*` ハンドラは `registry.get(provider).xxx` を呼ぶよう変更する。

## 5. Claude Agent SDK / CLI の主な仕様

### パッケージ
```bash
npm install @anthropic-ai/claude-agent-sdk
```
- TypeScript SDK は `claude` CLI バイナリを optional dependency として同梱。
- 個人利用前提のため、ユーザー（＝自分）は事前に Claude Code をインストール・ログイン済みとする。
  実行時はローカルの `~/.claude/` 資格情報を CLI が参照する。

### ストリーミング Query API
```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "…ユーザー入力…",
  options: {
    cwd: workdir,                    // 作業ディレクトリ
    model: "claude-opus-4",          // モデル
    permissionMode: "acceptEdits",   // 権限モード
    allowedTools: ["Read", "Edit", "Bash"],
    maxTurns: 15,
  }
})) {
  if (message.type === "assistant") { /* 逐次UI反映 */ }
  if ("result" in message)          { /* 最終結果 */ }
}
```

### sandboxMode → permissionMode マッピング案
| Cotaska `sandboxMode` | Claude `permissionMode` |
|---|---|
| `read-only` | `plan` |
| `workspace-write` | `acceptEdits` |
| `danger-full-access` | `bypassPermissions`（要 opt-in・警告） |

### 認証状態チェック
- `codex doctor` の直接的な等価物は**無い**。環境変数の有無確認＋軽いテストクエリで代替判定する。

## 6. 設定・UI・実装の変更方針

### 6.1 settings.yaml（settingsService.js）
`DEFAULT_SETTINGS.aiChat` に以下を追加。
```yaml
aiChat:
  provider: "codex"           # 追加: "codex" | "claude"
  workdir: ""                 # 既存（両プロバイダ共用）
  sandboxMode: "read-only"    # 既存（Claude では permissionMode に変換）
  ...
  claudeModel: "claude-opus-4"  # 追加（任意）
  claudeAuthMode: "local"     # 追加: "local"（ローカルサブスク）| "bedrock"（クラウド）
  # Bedrock 用（claudeAuthMode = "bedrock" のとき使用）
  bedrockRegion: ""           # 例: us-east-1
  bedrockModelId: ""          # 例: anthropic.claude-...
  # AWS 資格情報は settings.yaml に平文で置かず、環境変数 / OS資格情報ストアを利用
```
- `provider` を `mergeSettings` で正規化（`["codex","claude"]` 以外は `codex` にフォールバック）。
- `claudeAuthMode` を正規化（`["local","bedrock"]` 以外は `local` にフォールバック）。
- `renderSettingsYaml` にコメント付きで `provider` / `claudeAuthMode` 行を追加。
- **AWS 資格情報（アクセスキー等）は `settings.yaml` に平文で保存しない**。環境変数、または OS 資格情報ストア（Electron `safeStorage` 等）での保管を検討する。

### 6.2 設定画面（SettingsPane.jsx）
- AI 設定セクション先頭に **「連携先」セレクト**（Codex / Claude Code）を追加。
- `provider === "claude"` のとき、Claude 用のモデル選択・認証状態チェック表記に切替。さらに **「認証方式」セレクト（ローカル / クラウドプロバイダ(Bedrock)）** を表示。
  - `claudeAuthMode === "local"`: ローカルの Claude Code 認証を利用（個人利用限定の注記を表示）。
  - `claudeAuthMode === "bedrock"`: リージョン / モデル ID / AWS 資格情報の入力欄を表示。従量課金・要 AWS セットアップの注記を表示。
- サンドボックス/権限の表記も provider により切替。

### 6.3 main.js（IPC）
- `aiChat:sendMessage` / `checkAuthStatus` / `cancelRun` / `listActiveRuns` / `listRunEvents` を provider ディスパッチへ変更。
- `onEvent` による `aiChat:runEvent` 送出、返却スキーマ（`ok` / `assistantMessage` / `error_kind` 等）は**両プロバイダで統一**。
- DB 系ハンドラは `aiService` のまま変更不要。

### 6.4 claudeCodeService.js（新設）
`codexSdkService.js` を雛形に同一シグネチャで実装。
1. SDK 動的 import、`claude` バイナリ解決。
2. `query({ prompt, options })` の async iterable を回して `emitRunEvent` で UI へ流す。
3. `permissionMode` は sandboxMode から変換、`cwd` は workdir、参照ファイル前置きは共通化して流用。
4. キャンセルは `AbortController` を接続。
5. `checkAuthStatus` はテストクエリで代替、返却スキーマは Codex と統一。
6. **認証モード分岐（`claudeAuthMode`）**:
   - `local`: ローカルの Claude Code 認証（`~/.claude/`）を利用。追加の環境変数注入なし。
   - `bedrock`: SDK 起動時に `CLAUDE_CODE_USE_BEDROCK=1` と AWS 資格情報（`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_REGION` 等）、モデル ID を環境変数として注入する。
   - `checkAuthStatus` もモードに応じて確認内容を切替（local は `~/.claude` 認証、bedrock は AWS 資格情報 + Bedrock 到達性）。
   - ※ Bedrock の正確な環境変数名・対応モデル ID・SDK での渡し方は実装時に最新ドキュメントで確認する。

## 7. 認証モード別の配布可否と運用ルール（重要）

Claude 連携は認証モードによって配布可否が異なる。**この区別を厳守する。**

| Claude 認証モード | 配布可否 | 運用ルール |
|---|---|---|
| **ローカルサブスク認証** | ❌ 配布不可（個人利用限定） | 配布ビルドに含めない。露出しない |
| **クラウドプロバイダ(Bedrock)** | ✅ 配布可（規約クリーン） | 配布可。ただし AWS 従量課金・セットアップ要の注記が必要 |

### 7.1 ローカルサブスク認証（個人利用限定）の担保
- **配布ビルドではローカルサブスク認証モードを無効化/非表示にする**（`claudeAuthMode === "local"` を選べない、または Claude プロバイダ自体を開発ビルド限定にする）。
- ローカル認証での利用は、あくまで本人のローカル開発環境限定とする。
- 実装上のガード例: 配布ビルド判定フラグで `claudeAuthMode` の選択肢を `bedrock` のみに制限する。

### 7.2 Bedrock モードの取り扱い
- Bedrock モードは第三者アプリの公式サポートパスであり、**配布ビルドに含めてよい**。
- ただし AWS アカウント・Bedrock 有効化・Claude モデル利用申請・資格情報が必要で、従量課金である旨を設定画面で明示する。
- AWS 資格情報は平文保存しない（`safeStorage` 等）。

### 7.3 共通
- 本方針を `DECISIONS.md` に記録する。
- 将来 Anthropic が第三者向けのサブスク連携を公式に許可した場合、または本人が事前承認を取得した場合に、ローカル認証の配布対象化を再検討する。

## 8. リスク・留意事項

- **規約**: 個人利用でも「明確に許可」ではなく「明確な違反にもなりにくいグレー」。配布した瞬間に不可となる前提を明確に持つ。
- **ToS 原文の再確認**: Anthropic / OpenAI の規約は変わりうる。実装・運用の節目でライブ原文を再確認する。
- **返却スキーマ統一**: UI 改修を最小化するため、Claude 側の応答も Codex と同じ形に揃える。
- **モデル ID・permissionMode**: SDK バージョンで変わりうるため実装時に最新を確認。

---

## 9. 決定事項

- アーキテクチャは `aiProviderRegistry` によるプロバイダ切替とし、既存の Codex 実装・DB・UI を最大限流用する。
- Claude 側は認証モードを2系統持つ（設定画面で選択）:
  - **ローカルサブスク認証**（`~/.claude/`）… 手軽だが **個人利用限定・配布不可**。Cotaska は認証情報を保持しない。
  - **クラウドプロバイダ(Bedrock)**（`CLAUDE_CODE_USE_BEDROCK=1` + AWS 資格情報）… 規約クリーンで **配布可**。従量課金・AWS セットアップ要。
- 配布ビルドではローカルサブスク認証モードを無効化/非表示にし、Bedrock モードのみ配布対象とする。
- 仕様変更票 **CHG-102** を起票し、実装タスク（T-0436〜T-0438）を登録する。
