## 目的・背景

AIがチャット途中で質問しても、現在のCotaskaでは回答を現在の処理へ渡せない。処理中の入力は送信予約となり、処理終了後の別のターンで送信される。

将来的に「AIが質問する → Cotaskaが回答待ちと回答欄を表示する → 利用者が回答する → AIが回答を受けて作業を続ける」を実現するため、現行のCodex TypeScript SDK方式を残し、Codex app-server方式を追加する。利用者からの指示により、今回はタスク登録と検討方針の記録のみを行う。実装・既定方式の変更・配布は未着手。

## 調査時点の整理（2026-10-24）

- 使用中の @openai/codex-sdk 0.160.0 はrunStreamed()で処理結果を受け取る方式で、実行中のターンへの追加入力や質問回答を扱う公開APIがない。
- app-serverには実行中の追加入力を扱うturn/steerと、質問回答を扱うitem/tool/requestUserInputがある。質問機能は実験的であり、着手時に同梱CLIのバージョン・対応モード・必要な機能設定を確認する。
- 通常の文章中の質問と、専用機能による質問要求は区別する。文章に疑問符があるだけで回答待ちに切り替えない。
- app-serverは同じPC上で動かせる。専用クラウドサーバーの契約を前提にしない。
- 方式の制約によって必ず失われる既存機能は調査範囲では見つかっていない。ただし、移行版での実動作は未検証であり、下記の検証完了まで互換性を保証した扱いにしない。

## 採用する検討・実装方針

1. 現行SDK方式を削除せず、内部の接続方式を選択できる構成でapp-serverを追加する。初期は現行方式を既定とし、明示的に切り替えて検証する。
2. Electron Main側でローカルのapp-serverと通信する。Rendererは既存のpreload bridge / IPCを経由し、Codexのプロセスや認証情報を直接扱わない。ローカルstdio接続を基本候補にする。
3. 現在のChatGPTログインを維持できる設計とし、APIキー入力や従量課金への切り替えを必須にしない。認証情報をタスク本文・設定・ログへ複製しない。
4. まず通常チャットと既存機能を維持する。検証後に、専用の質問要求による回答待ちUI、回答の返送、作業続行を追加する。turn/steerによる途中入力と従来の送信予約は意味が異なるため、操作と表示を区別する。
5. 既存のai.sqlite、添付画像、CotaskaスレッドとCodexセッションの対応を保持する。既存会話の表示と、AI側セッションの再開を別々に検証する。再開できない場合は既存の会話コンテキストによる復旧方針を引き継ぐ。
6. 切り戻しの手順・条件・制約を明文化する。方式切り替えは実行中を避け、処理が終了または中断した状態で行う。app-serverで作成した会話をSDK方式から継続できるかも確認する。
7. 切断・タイムアウト時に、ファイル変更やコマンドを含む依頼を自動で再送して二重実行しない。受信済み回答の重複、質問への二重回答、別スレッドへの混入を防ぐ。

## 料金・認証・利用条件

- app-serverへの変更そのものが、APIキー必須化や従量課金への移行を意味するわけではない。ChatGPTログインによる利用を維持する方針。
- 利用できるモデル、利用枠、追加クレジット等の条件はアカウント・契約に依存する。質問と回答の追加でもAI処理は利用枠を消費し、移行によって無制限・無料になるわけではない。
- APIキー認証を選択した場合はAPI利用料金の対象となる。移行時に意図せず認証経路が切り替わらないことを確認する。
- 公式は既存のローカル／オープンソースアプリでのapp-server認証の継続利用を案内している一方、従来のapp-server認証の商用・ホスト型サービスでの利用は認めていない。Cotaskaの提供形態と条件を着手時に再確認し、有料・クラウドサービスとして提供する場合はSign in with ChatGPT等の適用条件を別途確認する。

## 既存機能への影響と検証対象

| 対象 | 維持方針・確認内容 |
|---|---|
| 通常チャット・ファイル操作・コマンド | 現在の作業フォルダと権限を引き継ぎ、応答・実行結果・失敗を正しく扱う |
| モデル・思考量 | 対応設定へ変換する。自動・明示指定、モデル別の対応、送信予約時点の設定保持を確認する |
| 速度優先モード | 現在の独自設定とセッション運用を調査し、同等性や差異を明示する |
| ファイル添付・画像貼り付け | 送信形式を合わせ、プレビュー・保存・送信後解除・失敗時の扱いを維持する |
| 履歴・会話再開 | 既存履歴の閲覧、既存セッションの再開、別環境でセッションがない場合の復旧を確認する |
| 処理途中の表示・通知・待機時間 | 新しいイベントを既存表示へ対応づけ、画面離脱・復帰と完了時の履歴同期を確認する |
| 中断・送信予約・並行実行 | 中断完了、予約の順次送信と停止・再開、別スレッドでの同時処理・イベント分離を確認する |
| 質問と途中入力 | 回答待ち・回答受付済み・続行・中断を区別し、通常文章の質問と混同しない |
| タスク管理・Claude連携 | Codex側に変更範囲を絞り、共有IPC・キュー・画面の変更による退行がないことを確認する |

## リスク・保守方針

- 常駐する子プロセスの起動・終了、切断、再接続を管理する必要があり、SDK方式よりCotaska側の保守範囲が増える。
- 複数スレッドでプロセスを共有する場合、プロセス障害の影響が広がり得る。プロジェクト切り替え・アプリ終了時も含めて管理単位を決める。
- 質問機能は実験的なため、検証済みのCodexバージョンを同梱し、更新時に再検証する。モデル変更によって回答待ちや質問頻度が変わり得ることも確認する。
- 今回の検討は接続方式を変更する方針であり、同じモデルでも回答品質・速度・利用枠消費が完全に一致することを保証しない。
