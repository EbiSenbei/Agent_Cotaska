- 主要な直接依存はすべてソースまたはビルド処理から参照されている。静的検索上、直ちに削除できる明白な未使用直接依存は確認できなかった。

### 脆弱性の状況

- 全依存を対象にした `npm audit`: 合計 30 件（critical 1 / high 23 / moderate 6）。
- 開発依存を除外した `npm audit --omit=dev`: 合計 10 件（high 6 / moderate 4）。
- 本番側の主な直接依存:
  - `adm-zip@0.5.17`: 細工した ZIP による過大メモリ確保・DoS。Cotaskaではバックアップ作成／復元と更新ZIP処理で利用しているため優先度が高い。修正版は 0.6.1。
  - `js-yaml@4.1.1`: merge key 等による計算量DoS。タスク、設定、リスト、インデックス、プロジェクト情報の読書きに広く利用している。4.3.2 への更新候補。
  - `markdown-it@14.1.1`: smartquotes 処理の二乗時間DoS。タスク本文・AI応答のプレビューで利用。14.3.2 への更新候補。
- 本番側の主な間接依存:
  - `@anthropic-ai/claude-agent-sdk` 配下の `@hono/node-server` / `hono`、および関連する `fast-uri`、`ip-address`、`qs` に指摘あり。SDK更新後に再監査が必要。
  - `chokidar@3.6.0` 配下の古い `picomatch` にReDoS等の指摘あり。chokidar 4 への更新時に監視動作を回帰確認する。
- 開発側では `electron-builder@26.8.1` 配下の `app-builder-lib`、`tar`、`@xmldom/xmldom` などに high / critical があり、`vite@8.0.0` と `vitest@4.1.10` にも修正版がある。配布物生成環境の安全性の観点から放置しない。

### 利用状況と整理候補

- `gray-matter` と `js-yaml` は一見重複するが、前者はMarkdown frontmatterの分離・結合、後者はYAMLデータ全般の解析・出力に使われており、現状は役割が異なる。
- `rcedit` は `scripts/afterExtract.cjs` から利用され、Windows実行ファイル調整に必要。
- AI SDK 2種はそれぞれ `claudeCodeService.js` と `codexSdkService.js` から利用されている。
- `sql.js` は本体のAI履歴DBとセットアップ資材の双方に存在する。削除候補ではないが、バージョン不一致を防ぐ同期方法の整理余地がある。
- `package.json` のビルド対象が `node_modules/**` 全体を含むため、実行時不要のファイルやoptional依存が配布サイズへ与える影響を、生成物の中身とサイズで別途確認する価値がある。

### 推奨する対応順

1. `js-yaml`、`markdown-it`、`vite`、`vitest`、`electron-builder` を現行メジャー内の修正版へ更新し、テスト・ビルド・起動確認を行う。
2. `adm-zip` を 0.6.1 へ更新し、バックアップ作成／復元、更新ZIP展開、異常ZIPの拒否を重点検証する。
3. Anthropic / OpenAI SDKを個別に更新し、各AIセッションの開始・継続・中断・再開と認証エラー処理を確認後、再度 `npm audit --omit=dev` を実行する。
4. `chokidar` 4 への移行可否を確認し、タスクファイルの追加・更新・削除、複数検索ルート、アプリ自身の書込み抑制を回帰試験する。
5. React / Electron / `sql.js` など残りを小さい単位で更新する。`sql.js` は `20_app/setup` 側も同時に揃える。
6. 更新後に `npm test`、`npm run build`、Portable／Installer生成、主要手動シナリオを確認し、監査結果と配布サイズを更新前後で比較する。

### 調査時の留意点

- 本調査では依存更新やロックファイル変更は行っていない。
- 監査件数は npm advisory データベースの更新により変動するため、実装着手時に再取得する。
- 調査時点では依存更新・回帰試験が未実施だったため、実装着手前は `status: todo` としていた。
