Cotaskaの知名度を上げたい

## 目的

Cotaskaを「ローカルで安全に使える、AIエージェント協業向けタスク管理ツール」として認知してもらい、継続的に使ってくれる候補ユーザーとの接点を増やす。

## ロードマップ

### レビュー結果

初版ロードマップは方向性の整理としては十分だが、実行計画としては以下が不足していた。

- 各フェーズの成果物が曖昧で、完了判定しづらい。
- 発信先ごとの役割分担がなく、どこから着手するか迷いやすい。
- 初回公開時に何を同時に出すかが未定義。
- 数値目標がなく、改善判断が感覚に寄りやすい。

そのため、以下のロードマップでは「期間目安」「成果物」「公開チャネル」「初回キャンペーン」「確認指標」を追加する。

### Phase 1: 価値提案を固める（1〜2日）

- 想定ユーザーを「個人開発者」「AIエージェントと一緒に開発する人」「ローカルファイル管理を好む人」に絞る。
- Cotaskaが解決する課題を、タスク正本がMarkdownで残ること、ローカルで完結すること、AIが追跡しやすいことの3点に整理する。
- 競合や近いツールとの差分を、タスク管理アプリではなく「AIと人間の作業ログが残る運用環境」として言語化する。
- 成果物として、1行キャッチコピー、100字紹介文、3行の価値説明、想定ユーザー別の刺さる一言を作る。

### Phase 2: 見せる素材を整える（2〜4日）

- スクリーンショット、短い操作動画、主要機能一覧、導入手順を用意する。
- 初見で理解できるキャッチコピーと説明文を作る。
- GitHub、Booth、note、SNSで使い回せる紹介文と画像を整備する。
- 最低限の素材は、メイン画面、詳細ペイン、Markdownタスクファイル、AIがタスクを更新する例の4枚にする。
- 操作動画は30〜60秒に収め、起動、タスク追加、詳細編集、Markdownとして残る流れを見せる。

### Phase 3: 公開導線を作る（2〜3日）

- 最新版ダウンロード先、更新履歴、使い方、問い合わせ先が迷わず辿れるページを用意する。
- GitHubリポジトリや配布ページからCotaskaの特徴と安全な導入手順へ誘導する。
- ダウンロード後に最初の1タスクを登録できるまでの導線を短くする。
- 公開導線は「紹介ページ -> ダウンロード -> 初回起動 -> サンプルタスク登録」の順に確認する。
- GitHub README、Booth商品ページ、note記事、SNSプロフィールのリンク先を同じ導線へ揃える。

### Phase 4: 初回公開キャンペーンを行う（1週間）

- noteで「AIと一緒に開発するためのローカルタスク管理ツールを作った」という紹介記事を公開する。
- SNSで、問題提起、画面紹介、操作動画、導入リンク、開発背景の5投稿を分けて出す。
- Boothまたは配布ページには、初回利用者向けに「まず1件タスクを作る」短い手順を置く。
- 初回公開後48時間は、リンク切れ、導入失敗、説明不足の修正を優先する。

### Phase 5: 継続発信を始める（4週間）

- noteやSNSで、開発背景、AI協業の運用例、機能追加の意図を定期的に発信する。
- 単なる機能紹介ではなく、実際の使い方、失敗談、改善過程をコンテンツ化する。
- リリースごとに「何が便利になったか」を短く伝えるテンプレートを作る。
- 週1本はnoteまたは長文投稿、週2〜3本はSNS短文投稿を目安にする。
- 発信テーマは「AI運用」「ローカルファイル管理」「開発ログ」「タスク正本」「Cotaska更新情報」に分ける。

### Phase 6: フィードバックと改善を回す（継続）

- 利用者のつまずき、導入失敗、分かりにくい表現を記録する。
- 初回体験、インストール、更新、タスク登録、AI連携の順に改善点を洗い出す。
- 反応があった導線やコンテンツを増やし、反応が薄いものは見直す。
- フィードバックは「導入」「使い方」「不具合」「要望」「発信反応」に分類してCotaskaのタスクへ登録する。
- 月1回、公開導線、投稿反応、ダウンロード導線、要望の傾向を見直す。

## チャネル別の役割

- GitHub: 開発者向けの信頼性、README、リリース履歴、ソース公開の導線。
- Booth: ダウンロードと配布、非開発者にも分かる商品説明。
- note: 開発背景、思想、使い方、AI協業の具体例。
- SNS: 認知獲得、短い動画やスクリーンショット、更新告知。
- Cotaska内タスク: 反応、要望、改善点の受け皿。

## 成功指標

- Cotaskaの説明を見た人が、何のためのツールか30秒以内に理解できる。
- 配布ページから最新版を迷わずダウンロードできる。
- 初回起動後に、ユーザーが自分のタスクを1件登録できる。
- note、SNS、GitHub、Boothなどから継続的に流入がある。
- フィードバックや改善要望がタスクとして蓄積される。

## まず狙う数値目標

- 初回公開から30日以内に、紹介ページまたは配布ページへの訪問を100件以上作る。
- 初回公開から30日以内に、ダウンロードまたは配布ページ上の入手アクションを10件以上作る。
- 初回公開から30日以内に、note記事またはSNS投稿への反応を合計10件以上作る。
- 初回公開から30日以内に、改善要望または感想を1件以上得る。
