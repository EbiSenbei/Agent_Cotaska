## 今回完了したこと

| 項目 | 結果 |
| --- | --- |
| 狭い表示幅 | 同一オリジンiframeをCSS viewport 390px・320pxにして、index/download/usage/examplesの計8ケースを実ブラウザー表示。全ケースで横スクロールなし。主要見出し・ボタン等のはみ出しなし |
| 320pxの修正 | AI機能の見出しで2pxの横はみ出しを検出。`.split-heading > div` の最小幅と360px以下の見出し30pxを指定し、再測定でcontentWidth 305＝clientWidth 305へ修正 |
| メニュー | 390pxでメニューを開き、ダウンロードを選択して正しいページへ遷移。遷移先でメニューが閉じていることを確認 |
| 画像の確認 | トップのAI画面・AI説明・タスク管理画像に拡大リンクを追加。AIチャット画像の1080×780 PNGをブラウザーで開けることを確認 |
| 初回手順 | 実装の入力欄名に合わせて「メモを入力...」と「編集モードへ切替」を案内。自動保存の説明を維持 |
| 実ダウンロード | ローカルサイト→download→最新版ボタンをブラウザーで操作し、公式GitHubのv0.5.1 EXE取得完了。371,791,788 bytes、公開SHA-256と一致 |
| 全編再生 | ローカルサイトの動画を最初から再生。currentTime 60／duration 60／ended true／error null／readyState 4を確認。ミュートではない状態。再生途中のシークで代用していない |
| 音声の検証 | サイト用動画をFFmpegで全編デコードし、入力音声 -16.06 LUFS・True Peak -1.42 dBTPを測定。正本MP4と同じファイルを使う。ブラウザーの実際の出音を耳で聴いた検証とは区別する |
| 外部チャネル | 利用者からnote・SNS・Boothは「未使用。これから準備したい」と回答。既存URLの探索・修正待ちではなく、新規開設後に公式入口へ統一する準備とした |

ブラウザーのviewport overrideも試したが、この環境では指定390pxに対し実測984pxとなり反映されなかった。この結果を390pxの合格証拠には使わず、同一オリジンiframeで計測・目視した8ケースを証拠とする。スマホ実機・タッチ操作・OS固有の動画操作は未確認。
iframeでは390px時clientWidth 375、320px時clientWidth 305。差の15pxは縦スクロールバーで、各ケースのscrollWidthはclientWidthと一致している。

最終修正後の相対参照は103件すべて有効で、既存未コミット変更の保護チェックも成功。JavaScriptの処理は今回変更しておらず、前回の8ケースを再実行せず結果を引き継いだ。
