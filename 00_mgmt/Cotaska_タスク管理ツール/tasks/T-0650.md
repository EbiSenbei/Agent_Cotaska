タスクの中に[]と会った時にチェックボックスとみなすようにしてほしい。
ただこの仕様がmarkdownの一般的な仕様か？確認してから実装するか検討する。

## 調査結果・採用方針

- 単独の `[]` をチェックボックスとみなす記法は、一般的なMarkdown仕様ではない。
- GitHub Flavored Markdown（GFM）のtasklist拡張と表示互換にし、GFM全体への準拠は今回の対象にしない。
- リスト項目の最初の段落が `[ ]` で始まる場合を未完了、`[x]` または `[X]` で始まる場合を完了として扱う。マーカー後に本文が続く場合は空白を必須とする。
- `-`、`*`、`+`、`1.`、`1)` のリスト、入れ子のリスト、引用内のリストを同じ扱いにする。リストとして成立するかは既存Markdownパーサーの解析結果に従う。
- マーカー後の強調、リンク、インラインコードなどは通常のMarkdownとして描画する。
- 単独の `[]`、リスト項目ではない `[ ]`、文章途中の `[ ]`、空白なしの `- [ ]項目`、`[  ]`、`[v]`、エスケープされた `\[ ]` はチェックボックスへ変換しない。インラインコード、フェンスコード、インデントコード内も変換しない。
- チェックボックス化はタスク詳細本文のMarkdownプレビュー表示だけを対象とする。編集モードではMarkdown原文を編集する。
- プレビュー上では元のリスト記号をチェックボックスへ置き換え、折り返し行を本文位置へ揃える。完了項目へ自動で取り消し線は付けない。
- チェックボックスは状態を読み取れるセマンティックなHTML要素として出力するが、表示専用かつ操作不可とする。状態変更はMarkdown原文の `[ ]` / `[x]` を編集して行う。
- 本文内チェックボックスは、タスク自体の `status`、`progress_status`、詳細ヘッダーの完了チェックとは連動させない。
- メインウィンドウとタスク詳細別ウィンドウへ適用し、AIチャット本文には適用しない。
- 空欄項目 `- [ ]` の動作保証、プレビューからの切り替え、原文の自動書き換え、進捗率計算、タスク完了連動、検索・抽出機能は初期スコープ外とする。
