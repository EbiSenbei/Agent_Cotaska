## 目的

速度優先モード時に、Codex SDKへ軽量な実行プロファイルを渡し、入力トークン量と応答開始待ちを削減できるか実装・検証する。

## 背景

T-0369の調査で、参照ファイルなしの短文でも `input_tokens` が約29.5kになることを確認した。
一方、Codex CLI直接実行でWeb検索とmulti-agentを無効化し、推論強度を `low` にしたところ、`input_tokens` が11,443まで下がった。

そのため、Cotaskaの速度優先モードでは、Fast modeだけでなくCodex側のツール/推論プロファイルも軽くする価値がある。

## 対応内容

- 速度優先モード時に以下のCodex configを渡す。
  - `service_tier = "fast"`
  - `features.fast_mode = true`
  - `web_search = "disabled"`
  - `features.multi_agent = false`
- 速度優先モード時に `ThreadOptions.modelReasoningEffort = "low"` を渡す。
- `minimal` は `image_gen` ツールとの互換性エラーが確認されたため採用しない。
- ログに以下を追加する。
  - `web_search_mode`
  - `multi_agent_enabled`
  - `model_reasoning_effort`
- 実装後、同じ短文質問で以下を比較する。
  - 現行速度優先
  - 軽量Codex実行プロファイル適用後

## 完了条件

- 速度優先モード時に軽量Codex実行プロファイルが適用されている。
- AIチャット送信が成功する。
- 入力トークン量と応答時間の比較結果が記録されている。
- 回答品質への影響が許容できるか判断できる。

## 実装メモ

`20_app/src/main/codexSdkService.js` に速度優先モード用の軽量Codex実行プロファイルを追加した。

速度優先モード時のCodex config:

```js
{
  service_tier: "fast",
  web_search: "disabled",
  features: {
    fast_mode: true,
    multi_agent: false,
  },
}
```

速度優先モード時のThreadOptions:

```js
{
  modelReasoningEffort: "low",
}
```

診断ログには以下を追加した。

- `web_search_mode`
- `multi_agent_enabled`
- `model_reasoning_effort`

## 検証結果

- 軽量Codex実行プロファイル適用後、`web_search_mode = disabled`、`multi_agent_enabled = false`、`model_reasoning_effort = low` がログで確認できた。
- 直前の実測17.049秒から13.458秒へ短縮し、初回イベント・初回AI本文までの待ち時間も改善した。
- その後T-0377で速度優先時のCodex短命実行を追加し、同一Cotaskaスレッドで複数回投稿しても `input_tokens` が約24kで安定することを確認した。
