## 現象

T-0776のAIチャットで、処理完了後にユーザーの最初の投稿しか表示されなくなった。ユーザーの画像付き報告に基づき調査した。

## 調査結果（2026-10-24）

- [x] 対象DBを読取専用で確認。21:53:44に保存されたassistantの最終回答175文字が残り、SQLite quick_checkもok。データ消失は確認されない。
- [x] インストール版v0.5.0のRendererバンドルと現行ソースで、実行終了時の履歴再取得漏れを確認。
- [x] 非表示Electronのモック検証で再現。外部で処理中の会話を画面に復元し、保存済み回答と実行完了をポーリングへ反映してもlistMessagesは1回のままで回答が表示されず、一時表示だけ消える。
- [x] 別スレッドを開いてから元のスレッドへ戻ると、履歴が再取得され保存済み回答が表示されることを確認。
- [x] 実行終了の検出を起点に、選択スレッドの保存済み履歴を再取得する修正を実施する。
- [x] AI画面の離脱・復帰、再マウント、画面を閉じている間の完了、通常送信、別スレッドへの混入防止、読込失敗・競合を検証する。
- [ ] ユーザーの実環境確認を記録する。

## 修正方針

処理中一覧からリクエストが消えた場合は一時表示のクリアだけで終了せず、保存済みのメッセージ・参照を再取得する。取得中にスレッドが変わった場合は反映せず、遅れて届いた古い履歴で新しい応答を消さないようにする。
DB・SDK・仕様の変更は現時点で不要。AI連携設計には、必要に応じて実行完了時の画面復元・同期を追記する。

初回対応は調査・記録のみ。その後の利用者の修正指示に基づく実装・検証結果を以下へ記録する。

## 修正・検証結果（2026-10-24）

- 画面に復元された実行の終了・リクエスト交代を検出し、選択スレッドのメッセージと参照を再取得する。通常送信は完了応答の同期を共用する。
- 選択スレッド・読込世代・マウント状態を確認し、切替前や送信前の古い履歴で新しい投稿を消さない。読込失敗時は既存表示を保持し、復元実行の同期は次のポーリングで再試行する。
- Mainの履歴・参照IPCは読込失敗を空配列に変換せず、内部情報を含まないエラーとして返す。DB・SDK・公開APIの追加変更なし。
- Node.js 22.23.4で36ファイル157単体テスト・本番ビルド成功。専用Electron検証13シナリオ（3投稿）、既存並列送信7投稿・待機時間3投稿・モデル選択3投稿（計16投稿）成功。モデル選択の既存検証は固定100ms待機で一度失敗・再実行成功後、保存状態が終了するまで待つ形へ修正し再度成功。実AI通信・利用者DBへの書込なし。
- 設計更新T-0807完了、ユーザー確認T-0808は未完了。親タスクはユーザー確認待ちとして仕掛を維持する。
- 再起動後に残存差分を確認して検証を継続した。既存作業差分を保持し、インストーラー再生成・インストール・公開・コミット・プッシュは行わない。先に生成済みのv0.5.1インストーラーには本修正を含まない。
