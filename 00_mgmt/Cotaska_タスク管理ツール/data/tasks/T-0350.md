CodexやChatGPTなどでは、処理中でもAIの途中の文章や作業状況が見える。
それと同じことが、CotaskaのAIモードでもできないか？

AIから返事が来るまで数十秒かかるため、待ち時間が嫌。

## 検討結果

対応可能。

Codex SDK には `run()` とは別に `runStreamed()` があり、
以下のようなイベントを処理中に受け取れる。

- `thread.started`
- `turn.started`
- `item.started`
- `item.updated`
- `item.completed`
- `turn.completed`
- `turn.failed`
- `error`

そのため、現在の「AI応答が完了するまで待ってから一括表示」ではなく、
Codex SDK から届くイベントを Electron main process から renderer へ逐次通知すれば、
CotaskaのAIモードでも処理中の内容を表示できる。

## 期待できる表示

ChatGPTのような完全なトークン単位の文字ストリーミングというより、
Codex SDK のイベント単位の途中表示として実装するのが現実的。

表示できる候補は以下。

- AIが考えている/応答を生成している状態
- reasoning summary が届いた場合の要約
- 実行中のコマンド
- コマンドの途中出力
- ファイル変更の開始/完了
- MCPツール呼び出しの開始/完了
- TODOリストの更新
- 最終的なAI応答本文

## 推奨仕様

最初の実装では、以下の表示を目標にする。

1. 処理中メッセージを固定文だけにせず、ストリーミングイベントで更新する。
2. `agent_message` が届いたら、AI応答欄を逐次更新する。
3. `command_execution` が届いたら、実行コマンドと出力を折りたたみ可能なブロックで表示する。
4. `file_change` が届いたら、変更対象ファイルの一覧を表示する。
5. `reasoning` が届いた場合は、短い「考え中」表示として扱う。
6. 完了時に、現在と同じく最終メッセージを `ai_messages` に保存する。

## データ保存方針

初期実装では、途中イベント全文をDB保存しなくてよい。

理由:

- まずは待ち時間の体感改善が目的。
- 途中イベントをすべて保存すると、DB設計と画面復元仕様が増える。
- 現状の `ai_messages` は会話本文、`ai_runs` は実行結果ログとして使えば足りる。

ただし、将来的に「実行ログ詳細を後から見たい」要望が出た場合は、
`ai_run_events` のようなテーブルを追加して、イベント履歴を保存する拡張余地を残す。

## 実装方針

現在:

- renderer が `aiChat.sendMessage()` を呼ぶ。
- main process の `codexSdkService.sendMessage()` が `codexThread.run(prompt, { signal })` を実行する。
- 完了後に `userMessage` と `assistantMessage` をまとめて返す。

変更案:

- `codexThread.run(prompt, { signal })` を `codexThread.runStreamed(prompt, { signal })` に変更する。
- main process で `for await (const event of streamed.events)` を処理する。
- IPCイベント、または専用購読APIで renderer に `request_id` 付きのイベントを送る。
- renderer は `request_id` が一致するイベントだけを現在のチャット表示に反映する。
- 完了時だけ `ai_messages` に最終応答を保存する。
- T-0347 の中断機能は同じ `AbortController` を使えるため、そのまま活かせる。

## 注意点

- Codex SDK のイベントは「文字が1文字ずつ流れる」ものではなく、item単位で届く。
- `agent_message` の更新タイミングはSDK/CLI側の出力仕様に依存する。
- コマンド出力やファイル変更を出す場合、チャット本文と作業ログを混ぜすぎないUI設計が必要。
- 中断時は、途中表示を「中断されました」に更新し、古いイベントが後から来ても画面を上書きしないようにする。

## 結論

実装する価値は高い。

特にAI応答に数十秒かかる場合、待機中の不安が減り、
「今ちゃんと動いているのか」が分かるようになる。

次の実装タスクとして切り出すなら、
「Codex SDK runStreamed を使ったAIチャット途中表示」として進めるのがよい。

## 実装メモ

推奨仕様に沿って、初期実装を追加した。

- `codexSdkService.sendMessage()` の内部処理を `codexThread.run()` から `codexThread.runStreamed()` に変更。
- main process で `for await (const event of streamed.events)` を処理し、途中イベントを renderer へ `aiChat:runEvent` で通知。
- preload に `aiChat.onRunEvent()` を追加。
- renderer は `request_id` が現在の送信と一致するイベントだけを処理中カードへ表示。
- 表示対象は `turn.started`、`turn.completed`、`agent_message`、`reasoning`、`command_execution`、`file_change`、`mcp_tool_call`、`todo_list`、`web_search`、`error`。
- コマンド出力は大きくなりすぎないよう main process 側で丸める。
- 中断は T-0347 の `AbortController` と同じ仕組みを継続利用。
- DB保存は初期方針通り、途中イベント全文は保存せず、完了時の最終AI応答のみ `ai_messages` に保存する。
