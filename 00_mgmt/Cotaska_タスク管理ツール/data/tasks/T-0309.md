## 目的

設定 > アプリ情報 > 更新確認をクリックした際に `fetch failed` が表示され、最新版確認できない問題を調査・対応する。

## バグレポート

- `10_docs/30_実装・検証/10_不具合対応/20260603_01_アプリ情報の更新確認でfetch_failedになる.md`

## 調査観点

- 会社ネットワーク環境で更新確認先 URL への通信が遮断または書き換えされていないかを確認する。
- プロキシ、SSL インスペクション、ファイアウォール制限時の失敗メッセージが十分か確認する。
- `latestVersionUrl` の設定値と取得処理が現行リリース環境で正しいか確認する。

## 実施メモ（2026-06-03）

- PowerShell の `Invoke-WebRequest` では `latestVersionUrl` とダウンロードページの両方が HTTP 200 で到達可能だった。
- 同梱 Node (`v22.14.0/node.exe`) の `fetch` では `TypeError: fetch failed` を再現し、`cause.code=ECONNRESET` / `Client network socket disconnected before secure TLS connection was established` を確認した。
- `20_app/src/main/main.js` に、Node `fetch` 失敗時の `electron.net` フォールバックと、ネットワーク原因を明示するエラーメッセージ・ログ詳細化を実装した。
- `release/win-unpacked/CotaskaCore.exe` で確認したところ、`updates.check()` の `unsupported` メッセージ（Cotaska-Portable 起動案内）が優先表示され、`app:checkForUpdates` の通常確認へ進まないことを確認した。
- `20_app/src/renderer/components/SettingsPane.jsx` の更新確認分岐を修正し、`updates.check()` が `unsupported` の場合は `app:checkForUpdates` へフォールバックするようにした。
- `npm run build` 成功を確認した。
