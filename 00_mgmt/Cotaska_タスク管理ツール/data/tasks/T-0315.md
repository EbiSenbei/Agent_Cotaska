## 目的

タスク一覧のドラッグ操作で、既存タスクの `parent` を更新し、別タスクの子タスクとして保存できるようにする。

## 完了条件

- ドラッグ中に親子紐づけ候補の行が分かる。
- ドロップ時に `parent` が更新され、タスクファイルへ保存される。
- 自分自身、子孫、最大階層超過へのドロップが無効化される。
- 既存の同階層並び替え操作が維持される。
- 親子紐づけ解除または直後の戻し導線が実装されている。

## 補足

実装前に T-0314 の設計結果とユーザー確認ポイントを反映する。

## 実施結果

- `MainPane.jsx` で、行中央へのドロップを子タスク化、行上下へのドロップを既存の並び替えとして判定するようにした。
- サブタスクもドラッグ可能にし、ドラッグ中は「子にする」「不可」の候補表示を出すようにした。
- 親を持つタスクをドラッグ中に「親なしに戻す」領域へドロップすると `parent: null` に戻せるようにした。
- `App.jsx` で `parent` 更新保存と、自己参照・子孫・5階層超過の事前判定を追加した。
- `taskService.js` で `parent` 更新時の自己参照・循環参照・最大5階層超過を main process 側でも拒否するようにした。
- Codex 同梱 Node.js で Vite production build 成功。
- 2026-06-25 追加対応: 子タスクを行上下へドロップした場合、ドロップ先タスクと同じ親階層へ `parent` を付け替えてから並び替えるようにした。
- 2026-06-25 調査対応: 子タスクのドラッグ開始が行側の `dragstart` に乗らない場合があるため、ドラッグハンドル自体も draggable にし、ハンドルから直接 `dragstart` できるようにした。
- 2026-06-25 追加調査対応: 行とハンドルの二重 draggable を避け、ドラッグ開始元をハンドルへ一本化した。子タスクのハンドルは常時表示し、当たり判定を広げた。
- 2026-06-25 追加調査対応: メイン一覧側では行本体が `draggable={false}` で、18px幅のハンドルのみがドラッグ開始点になっていたため、子タスク行を掴んだ操作ではドラッグが始まらなかった。完了・無効・階層警告タスクを除き、メイン一覧の行本体からも `dragstart` できるように変更し、チェックボックス・展開ボタン・期限操作などの操作部品はドラッグ開始対象から除外した。
- 2026-06-25 追加調査対応: `listSort.key === "order"` のときだけ `onReorderTask` を渡していたため、表示順を ID・日付・名前に変更しているとドラッグ開始自体が無効化されていた。親子変更のドラッグ開始はソート状態に依存しないよう、ゴミ箱・完了・検索以外では `onReorderTask` を渡すようにした。
- 2026-06-25 追加調査対応: 検索モード中は `dragEnabled` が false になっていたため、検索結果上の子タスクはドラッグできなかった。検索中もゴミ箱・完了以外ではドラッグを有効にし、タスク名の子要素自体にも `draggable` と `dragstart` を付与して、文字部分を掴んだ場合もドラッグ開始できるようにした。
- 2026-06-25 追加調査対応: モックDOM検証で展開後の子タスク行は `draggable=true` で描画されていることを確認した。Electron/Chromium のネイティブHTML5ドラッグ開始に依存しないよう、`mousemove`/`mouseup` ベースのフォールバックドラッグを追加し、行・タスク名・ハンドルから移動した場合も既存の親子変更/並び替え処理へ接続するようにした。
- 2026-06-25 ログ調査: ユーザー操作後に `tasks:reorder success` が記録され、T-0079/T-0080/T-0081/T-0083 の `sort_order` 更新とファイル変更を確認した。ドラッグ開始から保存までは到達しているため、以降は「ドラッグできない」ではなく「期待した親子解除/移動モードとして解釈されていない」可能性を主軸に調査する。
- 2026-06-25 追加調査対応: ドラッグハンドルは `button` 相当の操作部品としてフォールバックドラッグ開始条件に弾かれる可能性があったため、ハンドルからの開始時だけ操作部品除外をバイパスするようにした。
- 2026-06-26 ログ調査: 1回成功後の再操作で `pointer-started` と `native-started` が両方出ていた一方、drop/update が出ないケースを確認した。ネイティブHTML5ドラッグとフォールバックドラッグが二重に走り、ドロップ確定が不安定になっていたと判断した。
- 2026-06-26 追加対応: タスク行・タスク名・ドラッグハンドルのネイティブ `draggable` を無効化し、親子変更・並び替え・親なし戻しをポインター方式へ一本化した。日付/進捗セクションへの移動もポインター方式で判定できるよう、セクション識別属性と診断ログを追加した。
- 2026-06-26 確認: 再起動後ログで `pointer-drop-root` → `tasks:update T-0081` → `parent: null` の保存成功を確認した。
- 2026-06-26 ユーザー確認メモ: 動作自体は確認できたが、操作感がかなり不自然。特に子タスクを1回目のドラッグではうまく動かせず、2回ドラッグすると親なしにできることがある。次回はこの操作感の悪さと、1回目のドラッグで確定しない原因の調査から再開する。

- 2026-06-27 追加調査対応: ネイティブHTML5ドラッグの残存ハンドラを整理し、タスク行・ハンドルの親子変更/並び替え操作をポインター方式へ一本化した状態に揃えた。
