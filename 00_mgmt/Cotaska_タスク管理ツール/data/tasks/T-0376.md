## 目的

AIメッセージ保存時の `token_count` が実態より大きく見える問題を修正する。

## 背景

T-0359の応答速度調査中に、`ai_messages.token_count` が `input_tokens + cached_input_tokens + output_tokens + reasoning_output_tokens` で保存されていることを確認した。

Codex SDKのusageでは、`cached_input_tokens` は通常 `input_tokens` の内訳として扱うべき値であり、合計値へ別加算すると二重計上になる可能性が高い。

## 対応内容

- `20_app/src/main/codexSdkService.js` の token_count 集計処理を確認する。
- `cached_input_tokens` を二重加算しないよう修正する。
- 必要であれば、ログ表示・タスク調査メモ上の表現も「input_tokens」と「cached_input_tokens」を分けて扱う。
- 既存データの補正が必要か確認する。

## 完了条件

- 新規AI応答の `ai_messages.token_count` が二重計上されない。
- `input_tokens` と `cached_input_tokens` の関係が調査ログ上で誤解なく確認できる。
- AIチャット送信が正常に動作する。

## 対応メモ

- `20_app/src/main/codexSdkService.js` の `summarizeUsage()` を修正し、`cached_input_tokens` を `token_count` へ加算しないようにした。
- `token_count` は `input_tokens + output_tokens + reasoning_output_tokens` として保存する。
- 既存DBの過去値は調査時点の記録として残し、今回の修正では自動補正しない。
- 不具合対応記録として `10_docs/30_変更管理/20_バグレポート/20260704_01_AIメッセージトークン数が大きく表示される.md` を作成した。

## 検証

- bundled Node v22.14.0 で `npm.cmd run build` 成功。
- ユーザー動作確認で、複数回投稿後も `ai_messages.token_count` が `input_tokens + output_tokens + reasoning_output_tokens` と一致し、`cached_input_tokens` を二重加算していないことを確認済み。
