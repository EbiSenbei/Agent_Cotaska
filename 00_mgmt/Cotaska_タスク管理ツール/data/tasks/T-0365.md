## 目的

AIチャット送信ごとに `new Codex()` している現在の実装を見直し、Codex SDKインスタンスを使い回すことで初期化・接続準備の遅延を減らせるか確認する。

## 背景

T-0359では、CotaskaとCodex直接利用の応答時間差の要因候補として、送信ごとの `new Codex()` が挙がっている。

## 対応内容

- `20_app/src/main/codexSdkService.js` のCodex生成箇所を確認する。
- main process内でCodexインスタンスをキャッシュできるか検討する。
- 認証状態変更、エラー発生、アプリ終了時に安全に破棄・再生成できる方針を決める。
- 可能であれば実装する。
- 実装前後で同じ質問を再計測する。

## 注意点

- 複数スレッド同時送信時に状態が混線しないこと。
- 中断処理 `AbortController` と矛盾しないこと。
- Codex認証状態が変わった場合に古いインスタンスを使い続けないこと。
- 効果がない場合は、実装せず調査結果として残す。

## 完了条件

- Codex SDKインスタンス使い回しの可否が判断できている。
- 実装した場合は、AIチャット送信・中断・複数スレッド切替に問題がない。
- 実装前後の応答時間比較が記録されている。

## 対応メモ

- `20_app/src/main/codexSdkService.js` に Codex SDK クライアントのキャッシュを追加。
- `Codex` インスタンスは設定オプション単位で再利用し、会話スレッドは従来通り送信ごとに `startThread` / `resumeThread` で分離する方針とした。
- 診断ログに `codex_client_reused` を追加し、再利用されたか確認できるようにした。
- `npm run build` でビルド成功を確認。
