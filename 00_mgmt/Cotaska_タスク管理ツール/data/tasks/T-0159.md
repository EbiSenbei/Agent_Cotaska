## 作業内容

現在のCHG-058はCodex SDK限定のAI連携として実装する。
将来的にClaudeとも連携できるように、Codex固有実装を直接増やすのではなく、AIプロバイダを切り替えられる設計へ拡張する。

本タスクでは、Claude連携に必要な変更点、設計方針、実装項目を整理する。
Claude連携そのものの実装は、CHG-058本体の安定後に別タスクまたは後続仕様変更として実施する。

## 調査結果

調査日: 2026-06-28

### Claude側の利用入口

Claude連携には、主に以下の2案がある。

| 方式 | 概要 | Cotaskaでの扱い |
| --- | --- | --- |
| Claude Code CLI | `claude` コマンドをElectron main processから実行する。`claude -p "query"` により非対話実行でき、`--output-format json` / `stream-json` も利用できる。 | 初期導入はしやすいが、stdout/stderr、終了コード、セッションID、ストリーミングをCotaska側で正規化する必要がある。 |
| Claude Agent SDK | TypeScript/Python SDKからClaudeのエージェント機能を呼び出す。TypeScript SDKは `@anthropic-ai/claude-agent-sdk`。 | Electron main processとの相性がよい。将来の本命候補。SDK側でもRead/Edit/Bash等のツール権限を制御できる。 |

参考:
- Claude Code CLI Reference: https://code.claude.com/docs/en/cli-reference
- Claude Code Quickstart: https://code.claude.com/docs/en/quickstart
- Claude Code Authentication: https://code.claude.com/docs/en/authentication
- Claude Agent SDK Overview: https://code.claude.com/docs/en/agent-sdk/overview

### 認証方針

Cotaska内にClaudeのAPIキーやOAuthトークンは保存しない。

Claude Code CLIを利用する場合:
- ユーザーが事前にローカル環境で `claude` をインストールし、ログインする。
- Cotaskaは `claude auth status` などで認証状態を診断する。
- 未インストール、未認証、認証期限切れはCotaskaのAI設定画面に表示する。

Claude Agent SDKを利用する場合:
- 公式ドキュメント上は `ANTHROPIC_API_KEY` などの環境変数を使う方式が中心。
- CotaskaはAPIキーを保存せず、環境変数またはユーザーのローカル認証設定へ委譲する。
- SDK採用時は「Cotaska起動時にAPIキー入力を求める」のではなく、「認証状態を確認し、不足時に設定案内を表示する」方式を基本にする。

### 権限方針

Claudeはファイル読み取り、ファイル編集、コマンド実行が可能なエージェントとして動作し得る。
そのため、Cotaskaから利用する場合は既存のCodex方針と同じく、初期状態は安全側に倒す。

基本方針:
- 作業フォルダはCotaska設定の「作業フォルダ」配下に限定する。
- 初期権限は読み取り中心にする。
- Claudeが直接タスクファイルやソースを編集して完了させるのではなく、Cotaskaの `ai_action_proposals` に更新提案として保存する。
- ユーザー承認後にCotaskaが `update_task` / `create_task` / `update_file` を反映する。
- 書き込みやコマンド実行を許可する場合も、設定画面で明示的に変更できるようにする。

Claude Agent SDKでは `allowed_tools` に `Read` / `Glob` / `Grep` のような読み取り系ツールだけを指定することで、読み取り専用エージェントに近い構成を作れる。
CLI利用時も `--tools`、`--allowedTools`、`--disallowedTools`、`--permission-mode` などの指定を検討する。

## 必要な設計変更

### 1. AIプロバイダ共通層を追加する

現在の実装はCodex SDK前提の名前と責務が多い。
Claudeを追加する前に、以下のような共通インターフェースを定義する。

```text
AiProvider
- provider_key: codex | claude
- display_name
- checkAvailability()
- checkAuth()
- sendMessage()
- resumeThread()
- cancelRun()
- normalizeResponse()
- normalizeError()
```

実装イメージ:
- `codexProviderService.js`
- `claudeProviderService.js`
- `aiProviderRegistry.js`
- `aiService.js` はDB保存と共通フローに寄せる

### 2. SQLiteスキーマをプロバイダ非依存にする

Codex専用の列名を増やすと、Claude追加時に破綻しやすい。
以下のようにプロバイダ共通名へ寄せる。

| 対象 | 現状/想定 | 変更案 |
| --- | --- | --- |
| スレッド | Codex前提の外部ID | `ai_threads.provider_key`, `ai_threads.provider_thread_id` |
| 実行履歴 | `codex_run_id` 相当 | `ai_runs.provider_run_id` |
| メッセージ | AI応答本文 | `ai_messages.provider_message_id` を任意で追加 |
| 提案 | AI更新提案 | `ai_action_proposals.provider_key` または `run_id` 経由で判別 |

方針:
- Cotaska内部の主キーは `thread_id` / `message_id` / `run_id` を維持する。
- 外部AI側のIDは `provider_*` に分ける。
- `sandbox` のようなCodex寄りの名前は `permission_mode` / `execution_mode` / `tool_policy` のような共通概念へ寄せる。

### 3. 設定画面をプロバイダ対応にする

追加予定項目:

| 項目 | 内容 |
| --- | --- |
| 既定AIプロバイダ | `Codex` / `Claude` を選択 |
| 有効プロバイダ | Codexのみ、Claudeのみ、両方など |
| 作業フォルダ | 既存方針どおりCotaskaリポジトリルート等を指定 |
| プロバイダ別認証状態 | Codex / Claudeそれぞれの利用可否、未認証、未インストールを表示 |
| Claudeコマンドパス | CLI方式の場合、既定は `claude`。必要なら手動指定 |
| 権限モード | 読み取り専用、承認前提、書き込み許可など |
| 参照ファイル上限 | 既存方針どおり最大10件、合計文字数上限あり |

### 4. UIをプロバイダ対応にする

AIチャット画面に以下を追加する。

- スレッド一覧にプロバイダ表示を追加する。
- 新規スレッド作成時にプロバイダを選択できるようにする。
- 既存スレッドは作成時のプロバイダで継続する。
- チャットヘッダーに `Codex` / `Claude` のバッジを表示する。
- 未インストール/未認証時は送信欄を無効化し、設定画面への導線を出す。

### 5. IPC/APIをプロバイダ対応にする

RendererからMainへ渡すAIチャットAPIに `provider_key` を追加する。

例:

```javascript
window.cotaskaAPI.aiChat.sendMessage({
  thread_id,
  provider_key: 'claude',
  message,
  reference_files,
})
```

Main process側では `provider_key` に応じてプロバイダ実装を切り替える。
Rendererから直接CLIやSDKを呼ばない。

### 6. 応答とエラーを共通形式へ正規化する

CodexとClaudeで戻り値、ストリームイベント、エラー形式が異なるため、Cotaska内部では以下のような共通形式へ変換する。

```text
AiProviderResult
- provider_key
- provider_thread_id
- provider_run_id
- message_text
- raw_events
- token_usage
- exit_code
- error_code
- error_message
```

未インストール、未認証、権限不足、タイムアウト、ユーザーキャンセルは共通エラーコードにする。

## 実装方針

### Phase 1: Codex実装の抽象化

- Codex SDK呼び出しを `codexProviderService` に分離する。
- `aiService` からCodex固有名を減らす。
- DBに `provider_key` / `provider_thread_id` / `provider_run_id` を追加する。
- 既存Codexチャットの動作を維持する。

### Phase 2: Claude診断だけ追加

- `claude --version` またはSDKロード可否でインストール状態を確認する。
- `claude auth status` または環境変数状態で認証状態を確認する。
- 設定画面にClaudeの状態を表示する。
- この段階ではClaude送信はまだ有効化しない。

### Phase 3: Claude送信を読み取り専用で追加

- 初期は読み取り系ツールのみ許可する。
- 作業フォルダをCotaska設定値に固定する。
- チャット本文と参照ファイルをClaudeへ渡す。
- 応答を `ai_messages` に保存する。
- 直接編集ではなく `ai_action_proposals` への提案化を基本とする。

### Phase 4: 提案抽出・承認フローを共通化

- Codex応答、Claude応答のどちらからでも `ai_action_proposals` を抽出できるようにする。
- `update_task` / `create_task` / `update_file` を共通提案形式で保存する。
- 承認後の反映処理はプロバイダに依存させない。
