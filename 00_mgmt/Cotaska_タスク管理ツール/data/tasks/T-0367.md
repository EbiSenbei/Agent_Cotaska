## 目的

CotaskaのAIチャットに「速度優先」モードを追加できるか整理し、可能な範囲で設定として実装する。

## 背景

Codex公式情報ではFast modeや軽量モデルが速度改善候補として示されている。
ただし、Cotaskaの現行UIではチャット入力欄のモデル選択ボタンは不要としているため、設定画面側で扱うのが望ましい。

## 対応内容

- `@openai/codex-sdk` のTypeScript APIでFast mode相当、`service_tier`、モデル指定が可能か確認する。
- Codex config側の `service_tier = "fast"` / `[features].fast_mode = true` をCotaskaから安全に扱えるか確認する。
- 速度優先モードで行う内容を決める。
  - 参照ファイル送信抑制
  - 軽量モデル指定
  - Fast mode指定
- 設定画面へ追加する場合の項目名と初期値を決める。

## 完了条件

- Fast mode/速度優先設定の利用可否が明確になっている。
- 実装可能な項目について、設定画面または内部設定に反映されている。
- 実装しない項目は、理由と将来対応方針が記録されている。

## 調査結果

### Codex SDK TypeScript API

- `@openai/codex-sdk` の `ThreadOptions` には `model` と `modelReasoningEffort` があるため、モデル名と推論強度はSDK呼び出し時に指定できる。
- `CodexOptions` には `config` があり、SDK内部で `--config key=value` に展開される。
- Fast mode専用の `fastMode` や `serviceTier` のような一級プロパティは見当たらない。
- ただし `config` で `service_tier = "fast"` と `features.fast_mode = true` 相当を渡すことは可能。

### Fast mode利用可否

- Codex公式情報では、Fast modeは対応モデルの速度を上げる設定で、`service_tier = "fast"` と `[features].fast_mode = true` を `config.toml` に永続化できる。
- Cotaskaからは、ユーザーのCodex認証状態や契約がFast modeに対応しているかまでは事前に完全判定できない。
- そのため、既定は従来通り `standard` とし、ユーザーが明示的に選んだ場合のみ `speed` としてFast mode設定を渡す方針とする。

### 速度優先モードで今回実装する範囲

- 設定画面に `AI速度` を追加し、`標準` / `速度優先` を選択できるようにする。
- 設定値は `aiChat.performanceMode` として `standard` / `speed` で保存する。
- `speed` の場合、Codex SDK生成時に以下の設定上書きを渡す。

```js
new Codex({
  config: {
    service_tier: "fast",
    features: {
      fast_mode: true,
    },
  },
})
```

### 今回実装しない範囲

- 軽量モデル指定は今回見送り。
  - チャット入力欄のモデル選択ボタンは不要という方針がある。
  - `gpt-5.4-mini` のような軽量モデルは速度面では有利だが、回答品質や実装判断の深さが変わる可能性がある。
  - モデル切替を入れる場合は、設定画面で扱うか、スレッド単位で扱うかを別タスクで決める。
- 参照ファイル送信抑制は今回見送り。
  - 既に参照ファイル数と合計文字数の上限設定がある。
  - 速度優先時に参照を自動で削ると、ユーザーが添付した意図と異なる回答になる可能性がある。
  - 必要であれば「速度優先時は参照ファイルを送らない」設定を別項目として追加する。

## 実装メモ

- AI応答本文をアプリログに残すデバッグ出力は削除し、`response_chars` と `timings_ms` のみ記録する形に変更した。
- 速度優先モードの利用可否は、実行時のCodex側エラーまたは応答時間で確認する。
- 本タスクは動作確認待ちのため、ステータスは `仕掛` とする。
