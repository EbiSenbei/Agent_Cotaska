## 洗い出し結果

### 1. Codex認証状態確認の詳細が設計書に不足

不足している内容:

- `@openai/codex-sdk` 同梱Codex CLIを優先して使う方針。
- `codex doctor --json` を main process から実行する方針。
- グローバル `codex` コマンドだけに依存しない方針。
- 認証診断結果の生JSONや `auth.json` 内容を renderer へ渡さない方針。
- 現行実装のステータス区分:
  - `available`
  - `login_required`
  - `expired_possible`
  - `sdk_missing`
  - `cli_unavailable`
  - `error`
- `window.cotaskaAPI.aiChat.checkAuthStatus()` のIPC/API。

主な反映先:

- `10_docs/10_設計/20_基本設計/08_設定画面.md`
- `10_docs/10_設計/20_基本設計/06_AI連携.md`
- `10_docs/20_実装準備/40_仕様変更管理/20260514_CHG-058_ローカルAICLIチャット連携.md`

### 2. 設定画面のAI設定キーが古い

不足または古い内容:

- 設定画面設計に `codexSdk.workdir` という古いキーが残っている。
- 現行実装では `settings.yaml` の `aiChat` 配下に以下を持つ。
  - `workdir`
  - `sandboxMode`
  - `performanceMode`
  - `diagnosticsEnabled`
  - `retentionDays`
  - `maxReferenceFiles`
  - `maxReferenceChars`
- 「Codex SDK作業フォルダ」ではなく「作業フォルダ」という画面文言に変更済み。

主な反映先:

- `10_docs/10_設計/20_基本設計/08_設定画面.md`
- `10_docs/20_実装準備/40_仕様変更管理/20260514_CHG-058_ローカルAICLIチャット連携.md`

### 3. AIチャット認証エラー時の設定画面誘導が不足

不足している内容:

- AIチャット送信時に認証系エラーを分類する。
- 認証系エラーの場合、APIキー入力を促さず、設定画面のCodex認証状態確認へ誘導する。
- AIチャット画面には「設定で確認」ボタンを表示する。

主な反映先:

- `10_docs/10_設計/20_基本設計/06_AI連携.md`
- `10_docs/10_設計/20_基本設計/08_設定画面.md`

### 4. 速度優先モードと軽量Codex実行プロファイルが不足

不足している内容:

- 設定画面に `AI速度` として `標準` / `速度優先` を持つ。
- 速度優先ではFast mode要求に加え、以下の軽量プロファイルを適用する。
  - `service_tier = "fast"` 相当
  - `web_search = "disabled"`
  - `features.multi_agent = false`
  - `modelReasoningEffort = "low"`
- `modelReasoningEffort = "minimal"` は互換性エラーがあったため採用しない。

主な反映先:

- `10_docs/10_設計/20_基本設計/06_AI連携.md`
- `10_docs/10_設計/20_基本設計/08_設定画面.md`
- `10_docs/20_実装準備/40_仕様変更管理/20260514_CHG-058_ローカルAICLIチャット連携.md`

### 5. 速度優先時の短命Codexスレッド方針が不足

不足している内容:

- Cotaska側のAIスレッドとチャット履歴は維持する。
- 速度優先モードではCodex SDK側の既存 `codex_thread_id` を継続利用せず、短命Codexスレッドで実行する。
- 速度優先時の実行で得たCodexスレッドIDは `ai_runs` には記録するが、Cotaskaスレッドの保存済み `codex_thread_id` は上書きしない。
- 標準モードでは従来通りCodexスレッドを継続し、実装作業や文脈維持を優先する。

主な反映先:

- `10_docs/10_設計/20_基本設計/06_AI連携.md`
- `10_docs/20_実装準備/40_仕様変更管理/20260514_CHG-058_ローカルAICLIチャット連携.md`

### 6. ストリーミング表示の扱いが古い

不足または古い内容:

- `06_AI連携.md` ではストリーミング表示が後続拡張扱いのまま。
- 現行実装では `runStreamed()` のイベントを renderer へ送り、`agent_message` の途中本文をチャット欄へ逐次表示している。
- DB保存は最終応答を正本とし、途中断片は原則保存しない方針でよい。

主な反映先:

- `10_docs/10_設計/20_基本設計/06_AI連携.md`
- `10_docs/20_実装準備/40_仕様変更管理/20260514_CHG-058_ローカルAICLIチャット連携.md`

### 7. AI診断ログ設定化が不足

不足している内容:

- `AI_DIAGNOSTICS` ログは削除ではなく、設定画面の `AI診断ログ` でON/OFFできる正式診断ログとして残す。
- 既定値はOFF。
- ログには応答本文を残さず、応答時間、トークン数、Codexスレッド戦略などに限定する。

主な反映先:

- `10_docs/10_設計/20_基本設計/08_設定画面.md`
- `10_docs/10_設計/20_基本設計/06_AI連携.md`

### 8. DB設計変更は不要

確認結果:

- 今回の認証状態確認は、設定画面で都度確認する操作であり、認証状態を `data/ai.sqlite` に永続保存しない。
- `ai_runs.codex_thread_id` は既存設計にあり、速度優先時の短命CodexスレッドID記録にも使える。
- `ai_messages.token_count` の計算方針修正は既存カラムの意味の整理であり、新規カラムは不要。
