## 目的

CotaskaからCodex認証状態を確認するために、Codex SDK / Codex CLI / ローカルCodex環境で利用できる確認方法を整理する。

## 確認内容

- Codex SDKに認証状態確認APIがあるか確認する。
- Codex CLI側で認証状態を確認できるコマンドや挙動があるか確認する。
- `~/.codex/auth.json` 等の存在確認を使う場合の安全性と限界を整理する。
- 認証済み、未認証、期限切れ、SDK未検出、確認失敗をどのように分類できるか整理する。
- 診断結果に秘匿情報を含めない方針を明確にする。

## 調査結果

### Cotaska現行実装

- CotaskaのAIチャット機能は、Electron main process から `@openai/codex-sdk` を呼び出す実装になっている。
- `20_app/package.json` の dependencies に `@openai/codex-sdk` が含まれている。
- AI送信時は `20_app/src/main/codexSdkService.js` で `import("@openai/codex-sdk")` を行い、`new Codex()` してSDK経由でスレッドを開始・再開している。
- 現行のCotaska実装では、グローバルの `codex` コマンドやユーザーが別途インストールした `codex.exe` を直接 `spawn` / `execFile` していない。
- そのため、CotaskaのAIチャット実行に直接必要なのは「Cotaska側に `@openai/codex-sdk` が同梱またはインストールされていること」と「SDKが利用できる認証状態であること」。
- ユーザーが別途 Codex CLI や Codexデスクトップアプリをインストールしていることは、現行実装上の直接必須条件ではない。

### SDKとCLIの関係

- `@openai/codex-sdk` は、内部で `@openai/codex` のCodex CLIを起動し、標準入出力のJSONLイベントでやり取りする構成。
- `20_app/node_modules/@openai/codex-sdk/package.json` のバージョンは `0.142.3`。
- `@openai/codex-sdk` は `@openai/codex: 0.142.3` に依存している。
- Windows向けの同梱CLIは `@openai/codex-win32-x64` の optional dependency として配置される。
- ローカル確認では、同梱CLI `codex.exe` の `--version` が `codex-cli 0.142.3` として実行できた。
- 一方、グローバルの `codex` コマンドはWindowsApps配下のものが見つかったが、現在の実行環境では `Access denied` で実行できなかった。
- 認証状態確認は、グローバルの `codex` コマンドに依存せず、SDKが利用する同梱CLIを優先して実行する方針が安全。

### 認証情報の扱い

- Codex CLI / SDK は、ChatGPTログインまたはAPIキー相当の認証を利用できる。
- CLIと拡張機能はローカルにログイン状態をキャッシュする。
- キャッシュ先は構成により異なり、代表例は `CODEX_HOME` 配下の `auth.json`、またはOSの資格情報ストア。
- `CODEX_HOME` 未指定時の既定はユーザーホーム配下の `.codex`。
- `auth.json` は認証情報を含む可能性があるため、Cotaskaでは内容を読まない。
- Cotaska内にAPIキー、アクセストークン、`auth.json` の内容を保存しない方針を維持する。
- `auth.json` が存在しない場合でも、OS資格情報ストアに保存されている可能性があるため、「未認証」と断定してはいけない。
- `auth.json` が存在する場合でも、期限切れや権限不足の可能性があるため、「認証済み」と断定してはいけない。

### SDK APIとしての認証状態確認

- `@openai/codex-sdk` の公開型定義と実装を確認した範囲では、`checkAuth()` のような専用の認証状態確認APIは見当たらなかった。
- SDKの `CodexOptions` には `apiKey`、`env`、`config` 等の指定はあるが、既存ログイン状態を判定するための直接APIは確認できなかった。
- したがって、設定画面の認証状態確認は「SDKの公開APIだけで完結」ではなく、「SDK同梱CLIの診断コマンドを安全に呼ぶ」方式を採用するのが妥当。

### Codex CLIで利用できる診断

- Codex CLIには `codex doctor` があり、インストール、設定、認証、実行環境などを診断できる。
- `codex doctor --help` の確認結果、`--json` オプションで伏せ字済みの機械可読レポートを出力できる。
- そのため、Cotaskaのmain processでは、SDK同梱CLIのパスを解決し、`codex doctor --json` を実行して結果を解析する方式を第一候補とする。
- 生の診断結果をそのまま画面表示・保存せず、Cotaska側でステータスと短い案内文に変換する。
- `codex login` はログイン操作用、`codex logout` は認証削除用であり、設定画面では直接実行せず、ユーザーへの案内に留める。

## 採用方針

### 認証状態確認の第一候補

1. Electron main processで `@openai/codex-sdk` の存在確認を行う。
2. `@openai/codex` / `@openai/codex-win32-x64` 由来の同梱 `codex.exe` を解決する。
3. 同梱 `codex.exe --version` でCLIが起動できるか確認する。
4. 同梱 `codex.exe doctor --json` を実行する。
5. JSONのうち秘匿情報を含まない必要最小限の診断結果だけを抽出し、Rendererへ返す。

### 補助確認

- `CODEX_HOME` が設定されている場合はそのパスを、未設定の場合は既定の `~/.codex` を診断対象として扱う。
- `auth.json` の存在確認は補助情報に留める。
- `auth.json` の内容は読まない、表示しない、保存しない。
- OS資格情報ストア利用時は `auth.json` が存在しないことが正常な場合もあるため、ファイル有無だけで未認証判定しない。

### ステータス分類

CotaskaのIPC戻り値では、少なくとも以下の区分を返せるようにする。

| status | 意味 | 画面表示の方向性 |
| --- | --- | --- |
| `authenticated` | Codex診断で認証利用可能と判断できた | 認証済み |
| `login_required` | 認証情報がない、またはログインが必要 | Codexログイン案内を表示 |
| `expired_or_invalid` | 認証情報はある可能性があるが期限切れ、無効、権限不足 | 再ログイン案内を表示 |
| `sdk_missing` | `@openai/codex-sdk` を読み込めない | 依存関係の不足として表示 |
| `cli_missing` | SDK同梱CLIを解決できない | Codex CLI同梱不備として表示 |
| `cli_unavailable` | CLIは見つかったが起動できない | 実行権限・ウイルス対策・インストール破損の確認を促す |
| `unknown` | 診断出力を分類できない | 詳細確認が必要として表示 |

### セキュリティ方針

- CotaskaはAPIキー、アクセストークン、`auth.json` 内容を保存しない。
- 診断ログをCotaskaのDBやタスクファイルへ自動保存しない。
- 画面表示は `status`、短い説明、推奨アクションに限定する。
- `doctor --json` の生JSONはRendererへそのまま渡さない。
- 認証状態確認はユーザー操作または設定画面表示時の軽量チェックとして実行し、AIチャット送信前には必要に応じて直近結果を再確認する。
