本体コードを触らず、`workspace/temp/` の使い捨てスクリプトで `@anthropic-ai/claude-agent-sdk` の実挙動を検証する。設計(T-0436)を確定する前提づくり。

## 検証観点
- ローカルの Claude Code 認証（`~/.claude/`）で SDK が起動できるか
- `query()` のストリーミングイベントの粒度（Codex の runStreamed との対応）
- キャンセル（AbortController）が効くか
- 作業ディレクトリ(cwd) / model / permissionMode の指定が通るか

## 検証結果（詳細は workspace/temp/20260713_02_ClaudeSDK_PoC/PoC結果メモ.md）
- SDK導入・`query()` ストリーミングは成功。イベントは `system(init) → assistant → result` の順。
- **実環境は Bedrock 認証だった**（CLAUDE_CODE_USE_BEDROCK=1 / AWS_PROFILE=claude-code / ap-northeast-1）。Bedrockモードは実機動作確認済み。ローカルサブスク認証は別環境で要確認。
- 既存 codexSdkService のストリーミングループ構造を流用でき、イベント種別マッピングの差し替えで対応可能。
- キャンセルは Codex と挙動が異なり、abort時は例外を投げず result 未受信で静かに終了 → 「result未受信で終了＝中断」と判定する設計が必要。
- usage 項目が Codex と異なる（input/output/cache tokens・total_cost_usd）。変換が必要。
