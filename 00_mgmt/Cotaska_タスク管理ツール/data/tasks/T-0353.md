## 背景

Cotaska は OpenAI APIキー、Codex access token、ChatGPTログイン情報をアプリ内に保存しない方針としている。
Codex SDK実行時の認証は、Codex SDK / ローカルCodex実行環境側のログイン状態を利用する。

現状は、未認証や認証切れの場合に Codex SDK 実行エラーとして表示されるが、ユーザーが設定画面から事前に状態を確認したり、ログイン方法を確認したりする導線が不足している。

## 対応内容

- 設定画面のAI関連設定に「Codex認証状態」セクションを追加する。
- Cotaska内に認証情報を保存しない旨を明記する。
- Codex SDK / ローカルCodex環境の認証状態を確認するボタンを追加する。
- 認証状態の表示区分を用意する。
  - 利用可能
  - ログインが必要
  - 期限切れの可能性
  - SDK未検出
  - 確認失敗
- 未認証または期限切れの可能性がある場合は、Codex側でログインするための案内を表示する。
- 認証エラー時、AIチャット画面にもAPIキー入力を促さず、設定画面の認証案内へ誘導する。
- `~/.codex/auth.json` 等の秘密情報の内容は、Cotaskaで表示・複製・保存しない。

## 実装メモ

- renderer から main process へ認証状態確認を依頼するIPCを追加する。
- main process 側で Codex SDK / Codex CLI 相当の認証確認方法を調査し、可能な範囲で軽量な確認を行う。
- 厳密な認証状態確認がSDKから提供されない場合は、短い診断実行または既知の認証ファイル存在確認とエラーメッセージ分類を組み合わせる。
- 診断結果には秘密情報を含めない。
- 設定画面にはログイン案内文、再確認ボタン、最後に確認した日時を表示する。

## 追加調査メモ（2026-07-05）

### Codex SDKの導入方法

- Codex SDKは、CotaskaのElectronアプリ側のnpm依存として導入する。
- TypeScript / JavaScript SDKの場合、導入コマンドは `npm install @openai/codex-sdk`。
- Cotaskaでは `20_app/package.json` の `dependencies` に `@openai/codex-sdk` が追加済み。
- そのため開発環境では `20_app` 配下で `npm install` すれば導入される。
- 配布版ではElectronアプリの依存として同梱する想定のため、利用者が個別に `@openai/codex-sdk` を手動インストールする運用にはしない。
- ただし、SDKが導入されていることと、ユーザーがCodexを利用できる認証状態であることは別問題として扱う。

### Codex利用時のユーザー認証

- CodexはOpenAIモデル利用時、主に以下の認証方法を利用できる。
  - ChatGPTアカウントでログインする。
  - OpenAI Platform APIキーでログインする。
  - Enterprise向けのCodex access tokenを利用する。
- Cotaskaの通常利用では、まずはChatGPTログイン済みのローカルCodex環境を利用する想定とする。
- 代表的なログイン方法は、ユーザーがローカル環境で `codex login` を実行し、ブラウザでログインを完了する方法。
- Codexはログイン情報をローカルにキャッシュする。代表例は `~/.codex/auth.json` またはOSの資格情報ストア。
- CotaskaはOpenAI APIキー、Codex access token、`auth.json` の内容を保存・表示・複製しない。
- CotaskaはSDKを呼び出す側に留め、認証情報の管理はCodex側に任せる。

### Cotaskaでのあるべき導線

1. Cotaskaを起動する。
2. 設定画面で「Codex認証状態を確認」できる。
3. 未認証または期限切れの可能性がある場合は「Codexにログインしてください」と案内する。
4. ユーザーが `codex login` 等でCodex側のログインを行う。
5. Cotaskaの設定画面で再確認する。
6. 認証済みであればAIチャットを利用可能にする。

### 現状実装との差分

- 現在の設定画面には、AI関連として「作業フォルダ」「権限」「AI速度」「AI診断ログ」「AI参照上限」「AIデータ削除」は存在する。
- 一方で、「Codex認証状態」セクション、認証状態の再確認ボタン、未認証時のログイン案内はまだ実装されていない。
- `window.cotaskaAPI` / preload / main process にも、Codex認証状態確認専用のIPCはまだ見当たらない。
- AIチャット起動時には作業フォルダ未設定の警告とAI DB確認はあるが、Codex認証状態の事前確認ではない。
- AIチャット送信エラー時も、現状はエラーメッセージをそのまま表示するだけで、設定画面の認証案内へ誘導する導線はまだない。
- したがって、上記のあるべき導線はT-0353の仕様として定義済みだが、現時点の実装には存在しない。
